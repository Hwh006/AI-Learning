# Memory 目录与使用说明

本目录保存与用户及其任务有关的长期记忆。[目录导航](索引.md) 说明各目录的用途和调用时机；[读取机制](读取机制.md) 说明怎样查询元数据并回读正文。本文件维护分类边界与来源性质，不汇总具体条目。

## 当前有什么

```text
memory/
├── README.md          分类边界、来源性质与维护入口
├── 索引.md            目录用途、调用时机与分类数量
├── 读取机制.md        范围选择、元数据查询与正文回读
├── 写入机制.md        分类、元数据、正文与更新规则
├── 写入Workflow.md    提交与迁移操作
├── 经历/              亲历、处境、想法、理解；外部观察是子类
├── 偏好/              特定场景下希望 Agent 怎样表达、判断或执行
├── 个人原则/          明确表达的判断准则、支持经历和例外
├── 个人目标/          现实生活中的长期方向
├── 项目/              正在做或做过的项目，其目标、方案和结果
├── 任务/              服务于个人目标或项目的行动及下一步
└── 决策方式/          一类情境中的关注因素、判据与取舍
```

分类数量见 [目录导航](索引.md)；具体条目由 [元数据查询工具](../tools/memory_catalog.md) 按需返回。`.gitkeep` 仅保留空目录，不算记忆。

README、索引和机制文档是管理文件，不是记忆条目，无需条目元数据，不参与候选筛选。

## 七类记忆怎样区分

| 类别 | 回答的问题 | 边界与关联 |
|---|---|---|
| 经历 | 发生了什么，当时的处境、想法和理解是什么？ | 外部观察用 `subtype: 外部观察`；模型归纳的协作经验用 `subtype: 协作经历`、`origin: conversation_experience`，不冒充用户亲口表达的想法 |
| 偏好 | 回复用户前需要检索哪些表达、交付及协作要求？ | 每轮回复前必须检索并应用适用偏好；执行方式偏好在行动前应用。保留条件与例外，不把一次修改扩大为长期要求 |
| 个人原则 | 用户明确以什么准则判断，哪些情境例外？ | 原则需明确表达，以经历或案例支持，不从一次选择推定人格原则 |
| 个人目标 | 用户在生活中的长期方向是什么？ | 与项目目标和具体行动分开，不从岗位、任务推测人生方向 |
| 项目 | 项目要达成什么，采用什么方案，结果怎样？ | 已有权威记录时只存定位和有来源的概述，不维护两套事实 |
| 任务 | 为哪个个人目标或项目做什么，下一步是什么？ | 标明关联对象与行动状态；只保存明确要求保留或需要跨任务续接的行动，不把所有临时待办永久保存 |
| 决策方式 | 面对一类场景，用户关注哪些因素，如何判断与取舍？ | 决策案例可以作依据；与希望模型怎样做的偏好分开，模型建议不当作用户决策方式 |

按主要内容选一个类别；多个方面通过 `related_ids` 或正文链接关联，不重复复制同一记忆。经历提供依据，原则与决策方式提供判断，个人目标提供方向，项目组织方案和结果，任务承接行动，偏好约束协作方式。

## 元数据与维护入口

每条必需字段为 `id`、`title`、`category`、`tags`、`summary`、`status`、`origin`、`created`、`updated`。不再使用 `description`；`scope` 为可选字段，只记录额外适用限制，不填写重复的通用用途。摘要控制在100–150字，说明内容、场景和关键边界；字段定义与写法见 [整理规则](写入机制.md)。

- 读取：[读取机制](读取机制.md)。
- 资格判断：根目录 [AGENTS.md](../AGENTS.md#前置识别与判断)。
- 分类与整理：[写入机制](写入机制.md)。
- 提交、迁移与删除：[写入 Workflow](写入Workflow.md)。
- 元数据及索引检查：`python3 tools/memory_catalog.py --check`。
- 元数据查询接口：[工具说明](../tools/memory_catalog.md)。
- 仅生成目录导航草稿：`python3 tools/memory_catalog.py`，输出到标准输出，不修改记忆。

`origin` 区分用户要求、用户陈述与模型归纳经验。`active` 只表示可供检索，不证明项目已完成、任务仍进行中或事实已独立验证；实时状态仍需核实实际依据。
