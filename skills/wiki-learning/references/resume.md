# 续学、复习与中断恢复

本文件用于已有学习档案时的执行。SKILL.md 定义整体职责；状态枚举、节点契约和字段以 state-machine.md 为准。无需每轮加载所有教学示例。

## 1. 先读什么

1. 从学习总览定位专题，再读该专题 state.json；总览只是导航，状态文件是续学依据。
2. 检查 schema_version、revision、当前会话 status／phase、active_unit_id、pending_question、repair_node。
3. 只读当前单元的学习证据、未解决弱点和手册对应段落；按缺口重新核对来源。
4. 当次可用时间未明确时问时间。上次的时间不自动带入本次。
5. 按手册链接核对讨论记录覆盖，接续原材料的逐字文件；正文教学已完成而归档或 Wiki 尚未完成时，续接相应交接阶段，不重做已通过题目，也不从摘要编造历史对话。

用户已经说“继续学习”时直接恢复，无需再问是否继续。可用一句话说明上次到哪里，但不重复整套学习地图和初始诊断。

若用户此前明确暂停以修正路线、指出章节遗漏或更换学习目标，先读取修订说明和材料覆盖导航，再决定恢复位置；此时不机械恢复旧题。旧证据保留，但只支持当时已检验的局部范围。需要改动旧待答项时保留原题和未答事实，按状态契约记录原因，不虚构跳过成绩。

从手册路线区及实际请求恢复材料驱动或知识地图驱动方向，规则见 [学习方向](learning-paths.md)。参考材料增多不自动切换方向，`map_ref` 存在也不代表必为地图驱动。地图因新 Wiki 更新时只复核受影响要点，保留旧证据与待答项。

换材料或进入新目标时，按 [材料分类与学习拆解](material-decomposition.md) 只调整受影响的候选单元与覆盖范围，再复核新依赖的专业概念；旧诊断只在原覆盖范围内有效。发现基础缺口时按 [诊断与路线规划](diagnosis-and-planning.md) 先补课并检查，保留原待答题与续接位置；已有充分证据的基础不反复摸底。仅更新 Skill 规则本身不构成重开已有课程的理由。

## 2. 按状态决定动作

| 当前状态 | 恢复动作 |
|---|---|
| paused 且有待答题 | 正常续学恢复原题；若暂停原因是修订路线，先按修订导航恢复，保留旧题为未答，不泄露答案 |
| paused 且停在 teaching | 依据讲解记录补足未完成部分，不假定已讲完 |
| 停在 understanding | 请用户表达理解；已有表达尚未反馈时先评价它 |
| 停在 practice／recall | 恢复原题；该题已有回答记录则先处理记录，不能再次记为一次新答题 |
| feedback 且有 repair_node | 简述缺口与纠正，按目标节点出新情境检查 |
| needs_review | 检查具体问题和前置基础，增加帮助或换例子；重学时清空当前 checks，保留历史 |
| completed 且 mastered=false | 先补未通过的部分，再换题检验；不机械从头上课 |
| blocked | 先检查阻塞是否已解除；未解除时补证或推荐其他有依据的单元 |
| finished | 展示完成情况，推荐复习或下一专题，不重置为未学 |

待答问题仍存在时，不能仅因为用户说“继续”就越过它。用户明确跳过则记录理由，不记录虚构答案或通过。

用户明确要求重新规划的情况按新目标处理，不受旧题优先规则阻止；记录旧题为何不再作为立即下一步。指定新材料时，核对其范围与既有手册的差异，不能将已有相近主题的成绩当作新材料覆盖情况。

## 3. 怎么复习

复习不是重放完整讲解。先用不同表述或新情境检查旧薄弱点；只有显示遗忘、混淆或新缺口时才补相应内容。

复习已掌握单元时，保留过去完成的证据；新一轮设 in_progress、mastered=false，清空当前 checks，新的题目和回答使用新 ID。通过后本轮即可重新确认掌握，不要求再等下一次。

同一道题刚展示过答案后答对，不作为独立回忆证据。旧错误已经解决时，在弱点和手册中标 resolved，下一次推荐不能继续把它当作仍然不会。

## 4. 处理多轮输入

- 用户回答选项：对应当前题评价，追加真实原答，再推进。
- 用户问为什么：先解释相关疑点，保持原待答项或明确说明换题原因。
- 用户指出题目有问题：暂停评分并核对，不先辩护、不先判错。
- 用户补充理解：结合原表达更新判断；有实质修正时用新记录保留前后变化。
- 用户切换主题：先保存原专题，再加载目标专题；两个专题的题目与记录分开。
- 用户调整目标：只重新规划受影响部分，保留已学证据，不强制全课重来。

## 5. 状态缺失、过期或不一致

有手册但无状态时，可以从手册恢复“记录过什么”，但不能把手册中的知识内容直接当用户已通过测验。将可恢复的事实与待验证的掌握程度分清，以少量检查补证。

版本冲突先读新文件再合并，不能反复覆盖。状态与手册矛盾时，以真实回答及保存记录核对，再修订概览；不能选择看起来更好的成绩。

来源失效时，先恢复学习节点，再核对受影响材料。原题的有效性可能需要重新判断，但不要无依据推翻所有旧进度。

## 6. 暂停交付

有文件系统时保存状态与实际发生的手册修订，给出文件链接、当前停点和下一步。没有文件系统时按 state-machine.md 的恢复包格式输出，明确哪些内容需要用户保留；不要声称后台记住了。

用户回来后只需提供原档案或恢复包，便可按节点接续。恢复时校验内容，不要求用户重新讲完整段历史。
