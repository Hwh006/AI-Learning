# Wiki 生成后同步 Map 工作流

## 触发与交接

已授权的 Wiki 生成或改写任务完成内容阶段后，自动接续本流程；无需用户另说“更新 Map”。仅讨论、草稿以及用户明确排除地图更新时不触发写入。

原文入库仍由 [raw-wiki-ingest](../raw-wiki-ingest/SKILL.md) 逐篇理解和闭合，不把多篇原文合成一次写作。交接输入为本次实际创建、重建、合并、改名或停用的 Wiki 路径，而非 raw 文件名、计划中的页面或来源页数量。知识生成方法和页型职责仍见 [index.md](../../index.md)。

单篇任务在内容校验后同步；连续队列逐篇记录变更路径，可以在每章或明确批次结束统一编排地图。内容完成与地图完成分别记录；所有地图批次完成前，不报告整个任务完成。后续合并改变页面主旨或链接目标时，重新检查原有归属。

## 1. 捕获范围与基线

先完成知识页自身的页型校验及适用的来源、关系校验。把实际变更路径写成 JSON 字符串数组，例如运行目录中的 `changed-pages.json`；它可含 source，工具会明确列为排除项。随后运行：

```bash
python3 tools/wiki_map_sync.py snapshot --pages-json <运行目录>/changed-pages.json --out <运行目录>/map-before.json
```

用户要求全库地图维护时省略 `--pages-json`。输入只能是已存在的 Wiki；source、raw、memory、历史页及不可检索页不挂地图。保存基线后，本阶段只改 Map；若知识正文必须修订，先回内容阶段完成修订，再重建地图基线。

## 2. 判断归属

读取 [wiki-map-page](../wiki-map-page/SKILL.md) 及现有地图。对本次知识页回读必要正文，判断领域、专题、子知识点和横向阅读关系；检查已收录页的原位置是否仍合适，不能只处理缺失页。

优先复用已确认领域与分支；出现有内容支撑的新子主题时在原领域内增补。领域新建或重大重分仍由用户决定；这不阻止维护已有领域中的明确归属。确实无法归类则登记待决项和具体原因，保持地图阶段未完成，不用临时杂项列表伪装覆盖。

在运行目录保存 `map-decisions.json`，每个需要新增或调整入口的页面一条：

```json
[
  {
    "page": "wiki/concepts/智能体运行时的组装执行与记录.md",
    "reason": "主体讲模型、工具和会话的运行时组装，归Harness运行框架；任务反馈循环另作横向入口。",
    "placements": [{"map": "wiki/map/AI.md", "heading": "4.1 运行框架与环境组装"}]
  }
]
```

记录实际正文依据，不由关键词脚本自动决定归属。原有入口适用时保留；同页可有多个合理入口。缺失页必须逐页记录决定，已有页复核结果可随本次批次记录保留。

确需迁移旧入口时，在同一决定附 `previous_placements`，内容取自基线中该页的 `existing_placements`；新的 `placements` 必须实际落链。不能删除旧入口却只填写“已有归属”，也不能改变已确认的领域划分来消除待决项。

## 3. 更新领域页与总入口

按 Map Skill 把链接写入真实分支，采用完整路径 wikilink。补新标题时同步页内目录；横向关系写明阅读目的。避免在地图尾部堆“本批新增”清单，也不复制知识页正文。

按有效知识目标去重刷新各领域 `coverage_pages`、更新时间及总地图的领域计数与去重总数。总地图日期、统计说明与实际范围一致，不把本批覆盖误说成全库覆盖。

## 4. 验收与完成

```bash
python3 tools/wiki_map_sync.py verify --snapshot <运行目录>/map-before.json --decisions <运行目录>/map-decisions.json --out <运行目录>/map-check.json
```

工具只读核对：本次适用页是否可从地图进入、决定是否落在指定标题下、所有地图链接与锚点是否有效、排除页是否混入、计数是否一致、旧入口是否保留，以及地图阶段是否意外改动知识页。工具不判断语义归属，仍须回读地图检查上下层和横向关系。

`map-check.json` 必须 `status: passed` 且本次 `missing` 为空才关闭地图阶段。全库维护还须 `global_missing` 为空。若确需移动或清理原入口，单独说明迁移映射并核对目标，不为通过校验静默删除有效旧链接。

最终交付同时列出实际知识页与实际更新的地图入口，并说明范围、覆盖结果及剩余待决项。不要用文件生成成功、知识页校验通过或交付清单替代地图完成。
