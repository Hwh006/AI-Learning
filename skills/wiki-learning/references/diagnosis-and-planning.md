# 诊断基础与安排学习路线

## 1. 先确定要形成什么能力

目标优先从用户当前请求与已有状态恢复。可用“能解释、能区分、能选择、能判断、能做出一个小结果”描述；只有“了解一下”时可以从入门单元起步，不为完善画像连续追问。指定材料未限制局部范围时，仍默认梳理全貌并覆盖主要知识，不能把入门起点当成只学摘要的范围。

有文章、书籍、课程或粘贴材料时，先承接 [材料分类与学习拆解](material-decomposition.md) 的候选单元、覆盖范围、缺口和预期能力，再按真实基础调整正式路线。材料拆解负责内容关系，本文件负责用户从哪里学、先补什么；已有路线且仅续学时不重复整份拆解。

仅提出主题或要求按 Map 学习时，先承接 [知识地图驱动流程](learning-paths.md#3-知识地图驱动学习) 从实际 Map 与 Wiki 组织的候选维度与知识点，再诊断起点；不能因为没有上传文件就跳过现有知识库，直接用模型印象确定全套课程。

| 已有输入 | 起步方式 |
|---|---|
| 主题、目标和材料都明确 | 承接材料拆解与结构覆盖结果，先展示全程目录、简要解释必要基础，再轻量确认理解 |
| 提出学习主题或要求按 Map 学习 | 先定位当前 Map 分支、核对关联 Wiki，再从目标与真实基础安排候选专题 |
| 只有长文／书／课程 | 按材料类型梳理全貌和候选单元，区分暂定结构与可教学范围，展示全程目录并解释必要基础后再确认理解 |
| 只有主题但没有相关 Map | 先查现有 Wiki 形成暂定路线并说明地图缺口；知识也不足时按学习方向的降级规则处理 |
| 没有主题、材料或记录 | 只问一个选择方向的问题，例如最近想解决什么问题 |

本次时间未给出时在安排当次学习量前单独询问；不阻止先展示全程目录和说明学习对象。不要把上次的“今天十分钟”当本次的时间。已经明确的学习方式和本 Skill 默认约定直接沿用。

## 2. 识别目标所需的前置概念

先读目标材料，找出理解当前知识点必须依赖的专业概念及其关系，再安排诊断。范围以目标需要为准，不把全书术语都变成必修课；也不能因为一个词看起来常见，就默认用户懂它在当前领域的含义。

例如学习上下文检索，可能需要先理解知识库、上下文窗口、RAG、文本块及分块、向量嵌入与向量存储；进入关键词检索机制时，还要确认词项匹配、TF-IDF 与 BM25 的必要基础。这是依赖识别示例，不是所有主题的固定词表，也不要求一次全部提问或从数学公式教起。

对每个必要概念，核对实际回答，把结论写进 `diagnosis.summary`：

- 已证实：能解释核心作用或在新场景中正确使用，注明回答依据与适用范围，可跳过重复讲解。
- 待补：明确说不会，或回答显示具体缺口，先安排基础讲解与验证。
- 尚未确认：只有自述、认得名称或无证据，用少量可理解的问题确认；不等同于不会。

已有 `diagnosis.completed=true` 不代表新材料所需概念全部已查。保留旧诊断及真实回答，只补新目标的缺口；不能由用户懂 RAG 推定其也懂 BM25 或 TF-IDF。

首次展示整体知识范围后，可以先询问用户大致熟悉哪些部分，再结合旧手册的真实反馈判断讲解详略；无需逐词盘问。记录可采用下表，嵌入手册的基础依据区，不新增必填 JSON 字段。

| 知识点／整体范围 | 用户当前描述 | 手册中的具体依据 | 暂定理解与不确定性 | 本次如何讲 |
|---|---|---|---|---|

例如用户说“知道向量检索按语义找内容，但不懂 BM25”，路线可简短连接向量检索，完整解释 BM25 的含义、必要性、核心作用和适用场景，再说明它与 BM25 索引及重排的区别。自述与旧记录不同以当前表述调整讲解，必要时轻量确认；自述不直接生成掌握成绩。

讲解详略与材料覆盖是两件事：有证据的术语可简讲，但它所在的原文章节和关系仍要呈现；原文列出的区块边界等核心内容不能因自评熟悉整个 RAG 而消失。按 [知识点讲解卡](teaching.md#知识点讲解卡先说明内容再检查) 准备内容后再出依赖它的题目。

### 教学层次与进入条件

准备讲解时区分以下层次，并向用户简短说明当前位置；不把全部内容统称为“必要基础”。

| 层次 | 回答什么 | 范围与进入条件 |
|---|---|---|
| 整体导航 | 要解决什么问题、将学哪些内容、各部分有什么关系 | 可在基础确认前给出简短预览；不要求用户复述完整方法，也不记作基础已通过 |
| 必要基础 | 理解下一段内容所需的对象、概念、作用与关键区别 | 依据具体理解证据决定讲解详略；不熟悉时讲清用途、含义、例子和相近概念的区别，再确认理解 |
| 标准流程 | 已有做法怎样把这些概念串起来，各步骤如何衔接 | 所用基础已有证据或刚完成补讲与理解确认后展开；流程讲解与流程复述不能替代基础教学和检查 |
| 目标新方法 | 材料在已有做法上改变什么、为什么、怎样实现 | 先确认它依赖的基础和原有做法，再按材料展开新增机制及条件 |

例如学习片段背景补充方法：知识库与模型上下文、文本块、向量表示与检索、BM25 的作用属于候选基础；分块、建索引、检索、融合与重排的衔接属于标准流程；依据全文生成块级背景并纳入两类索引属于本文新增方法。分类用于确定教学位置，不要求每个名词单独成课，也不要求先学完所有基础再接触任何流程；只检查当前内容实际依赖的部分。

基础确认应取得能说明概念作用、区别或在小情境中正确使用的真实表达；一段回答可以覆盖一组关联概念。给术语加括号释义、展示完整流程或让用户照着刚给出的步骤复述，都不能单独证明相应基础已理解。历史证据充分时直接复用，部分充分时只补缺口，不因本次纠正就把所有基础判为不会。

时间短时缩小本次学习范围，保留整体导航及未学位置；不能为赶完文章，把“基础→流程→新方法”压成一轮讲解后直接考整条链路。用户询问“这属于必要基础吗”时，先解释并校正教学层次，暂缓受影响的未答题，再从合适位置继续；该追问本身不作为概念答错或基础薄弱的证据。

## 3. 用少量实际题目判断基础

先简要解释当前要用的基础概念、作用和例子，再从最影响目标的两三个候选检查点起步，逐题取得真实回答，再按缺口扩展；这个数量不是忽略其他必要概念的上限。一段真实解释可以覆盖多个概念，不必机械逐词考试。覆盖充分时停止诊断，不做全书入学考试。

1. 从最关键、最基础的区别开始，先给必要解释，允许用户说不懂或选“不确定”。
2. 基础答对后换一个小场景，检查是否只是认得术语。
3. 不确定或答错时，先讲缺失前置概念；部分理解只补缺口，充分理解只概括关系和必要边界；用户已经明确不会时直接开始基础教学，不用一路追问更难内容。
4. 如需澄清，只问影响起点的一个问题；不要求长篇自述。

每道摸底题也应先确定答案与依据，再等真实回答。题目本身无法确定答案时不拿来测用户。用户自然提供的解释也可以作为诊断线索，但仅说“我学过”不直接算通过。

摸底题用用户能理解的情境和措辞，不能要求在几个均未解释的技术名称间猜选项。答对依赖明显错误选项的题，只证明该题表现，不足以推定相关基础都已掌握。

## 4. 诊断如何改变教学

| 实际表现 | 初始判断 | 下一步 |
|---|---|---|
| 不知道术语，也无法判断基本场景 | 尚无基础证据 | 从具体问题与完整例子开始，support=full |
| 认得词，但容易把相邻概念混为一谈 | 有印象，需要澄清区别 | 先讲最关键差异，support=guided |
| 基础题正确，解释有遗漏 | 有基础，边界待检验 | 少讲重复内容，补边界并做应用，support=coached |
| 能解释且能判断新场景 | 已有较强基础 | 从较高层单元或应用开始，support=independent |
| 回答信息不足、来源有争议 | 暂不能判断 | 保留不确定，不给能力标签；补证或换题 |

这只是当前专题的起点，随后按实际表现调整。摸底通过不直接将整个专题标记为掌握；必要的核心理解与应用仍要在对应单元留下证据。

基础教学复用教学细则：先用具体问题讲用途，再解释含义、例子和相邻概念的区别，请用户表达理解，并用新情境检查。尚未通过时换例子或补更早的依赖；不能因为助手解释过或用户说“懂了”就直接进入依赖它的目标内容。基础薄弱者可以只完成一个基础单元，不为赶完文章压缩这一步。

诊断完成时记录：检查覆盖了哪些概念、实际问了什么、用户怎么答、哪些已证实或仍待补、据此如何改变学习路线。基础补课作为正常 `units` 记录，用 `prerequisite_ids` 连接依赖它的目标单元；已会而跳过的内容保留诊断证据，不伪造完成教学或测验。不要生成没有回答支持的“用户薄弱画像”。

使用旧手册或作答缩减讲解时，向用户简短说明实际依据和适用范围。手册里出现过名词不等于用户理解；手册与状态不一致时核对实际作答，不能以局部证据跳过整篇的目录和核心内容。

## 5. 定义最小可学单元

单元围绕一个能连贯解释的概念组、章节或小任务，不直接等同于整篇长文，也不把每个名词拆成一整套考试。指定材料的单元须映射回真实标题、子标题和知识点。指定材料的候选单元按 [共同产物要求](material-decomposition.md#6-候选单元与记录方式) 形成后，再根据前置验证调整。每个正式单元具备：

- 稳定 ID 和清楚名称。
- 学完能解释或判断什么。
- 前置单元及其关系；教学推导的依赖注明是安排建议。
- 实际材料范围和引用，或者明确的通用知识标记。
- 一个导入问题、一个具体例子、一处常见混淆。
- 理解表达的关键标准、一个应用任务和最终题组的考察范围。

例如“RAG”太大，可拆为离线与在线职责、分块的作用、召回与生成质量的区别等。专题可能有多个单元，但每次先教一个；不要为满足固定数量硬拆成五个或十个。

## 6. 生成路线与推荐

推荐按下面的顺序做语义判断，不需要写成数值打分系统：

1. 用户修订目标或指出内容遗漏时先修复路线并记录旧待答项处理；正常续学有未答题时恢复原题。
2. 某个基础缺口阻碍目标单元：先补该缺口。
3. 有尚未解决的 needs_review 单元：优先推荐补讲或复习。
4. 前置条件满足的 pending 单元：选择最接近用户目标且适合当次时间的一个。
5. 大部分已掌握：用新场景复习关键边界，再进入下一专题。

已解决的问题不继续优先；纯粹年代久远不等于一定忘了。可以建议复习，但不在后台安排通知或重复任务。

首次先展示完整高层目录、原文章节对应与预期能力，短时学习也保留全流程认知，再说明基础验证后哪些需要先补、哪些可以直接开始；不要一次铺开全部章节细节。后续每轮展示“今天先学什么、为什么、接下来接什么”，整体安排留在手册路线区。无需逐单元请求批准。

## 7. 时间与进度

| 当次情况 | 合理安排 |
|---|---|
| 只有几分钟 | 恢复一个待答问题、解释一个缺口或完成一个小环节 |
| 有一段完整时间 | 一个知识点的讲解、理解表达、应用和最终检验 |
| 主题复杂 | 拆小单元，多轮完成；不能因为时间长就一次讲完整领域 |
| 用户说时间到了 | 在当前节点暂停，保存真实进展与下一动作 |

学习量根据内容和表现调整，不能承诺固定分钟数一定掌握。用户明确跳过时尊重选择，记录原因但不补造通过证据。

## 8. 退出条件

完成规划表示有可开始的单元、足够内容依据和检验安排；不表示用户已掌握。目标单元所需基础已证实，或已将缺口安排为先行教学单元，才可开始相应路线。缺材料时先解决材料缺口；缺基础时补基础；需要用户信息时一次只问一个关键问题。路线可以在新证据出现后修改，但不能静默删除已有进度。
