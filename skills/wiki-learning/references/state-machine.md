# 状态、节点与执行条件

本文件定义 Skill 的控制流程；`state.json` 保存一次学习执行到哪里及其证据。状态字段只能由实际事件改变，不能因为助手已讲解或用户说“继续”而推进。

## 一、入口模式

| 模式 | 进入条件 | 必须执行 | 退出条件 |
|---|---|---|---|
| `NEW` | 目标专题尚无有效状态 | 确定材料或主题，以未学状态建档，围绕候选专题摸底，再安排最小单元 | 有真实诊断和学习安排，进入讲解 |
| `CONTINUE` | 已有状态，用户要继续 | 恢复原节点和待回答问题；不重复摸底 | 原问题处理后进入对应下一节点 |
| `REVIEW` | 用户要求复习，或薄弱点影响后续学习 | 选择具体知识点，依据旧证据换题检查，必要时补讲 | 更新本轮证据和掌握状态 |
| `STATUS` | 仅查询进度／薄弱点／学过什么 | 读取并总结状态，关联文件 | 输出查询结果；不自动出题、改状态或开启学习 |

没有指定专题的 NEW／CONTINUE，先读学习总览和可用资料结构，由 Agent 推荐；有 Map 则使用 Map，无 Map 则依据资料或目标规划。建议改变专题时说明原因；用户当前明确选择优先。

## 二、三个独立维度

### 1. 单元流程 `units[].status`

| 值 | 定义／进入条件 | 触发动作 | 允许的后续状态 |
|---|---|---|---|
| `pending` | 尚未正式开始；没有教学或本单元检查证据 | 取证并进入讲解 | `in_progress` |
| `in_progress` | 已开始；理解、练习或测验尚未完成 | 按当前节点继续，禁止直接宣布完成 | `completed`／`needs_review`；暂停时保持 |
| `completed` | 已讲解，并取得理解表达、应用练习和整轮测验的真实回答；流程完成 | 检查 `mastered`，整理成果；未掌握者保留待巩固点 | 复习时 `in_progress`；新反证可转 `needs_review` |
| `needs_review` | 测验全错、核心理解错误，或同一知识点连续三次有效尝试仍卡住 | 直接纠错，换例子、增加帮助或补前置知识；不按完成推进 | 补讲开始转 `in_progress`，新证据通过后才可完成 |

三次是本 Skill 的默认重学触发阈值，用于避免反复原样重问；它不是对学习效果的科学保证。用户明确要暂停或切换时允许执行，原薄弱点保留，不形成死循环。

### 2. 掌握标志 `mastered`

| 证据 | 结果与处理 |
|---|---|
| 理解表达、应用练习、完整测验均通过 | `status=completed, mastered=true`；本轮即可确认掌握 |
| 两道最终题一对一错，或表达／应用仍有局部缺口 | 流程确已走完可为 `completed, mastered=false`，表示基本理解而待巩固；直接补讲后换题检查，不当作已掌握 |
| 最终题全错／核心理解错误 | `needs_review, mastered=false`，进入补讲，不自动推进 |
| 未回答、未做检查、只有自我确认 | 保持 `in_progress, mastered=false`；时间到时只暂停 |

默认最终测验两题，数量记录为 `recall_target=2`。用户明确调整时，在新题组开始前改目标并用 `recall_note` 记录原因；不因已看到错误答案而减少题数。`checks.recall` 保存本轮整组题的 ID，重测时整体替换，旧回答留在 `assessments`。不能从多轮失败中挑两个答对项拼成“本轮通过”。核心概念和适用边界都应覆盖，答案有争议时阻塞评分而非判错。

### 3. 运行状态 `session.status`

| 值 | 触发条件 | 处理 |
|---|---|---|
| `active` | 正常学习／用户要求续学 | 按 `phase` 工作 |
| `paused` | 用户停止、时间到或本轮不再推进 | 保存原 `phase`、待回答项和理由；不标完成；“继续”时恢复 |
| `blocked` | 原文缺失、题目有歧义、依据冲突或工具失败影响当前节点 | 记录具体原因，先补证；可保存原专题后切换有依据的单元，不能修改用户成绩掩盖阻塞 |
| `finished` | 本专题全部单元均有掌握证据，当前无待回答项 | 整理手册和下一专题建议；专题结束不代表整个领域学完 |

## 三、关键节点 `session.phase`

| 节点 | 进入条件 | 当前动作／等待对象 | 退出条件与去向 |
|---|---|---|---|
| `diagnosis` | 尚无覆盖当前目标前置概念的有效诊断，或用户要求重新评估 | 识别必要概念，对照旧证据补查缺口；逐题等待真实回答，明确不会者先安排基础教学 | 保存概念覆盖、回答与先补基础或直接进入目标的路线 → `planning` |
| `planning` | 诊断已有依据／目标发生变化 | 依据可用资料、薄弱点及前置关系安排或调整单元，确认当次时间 | 定位本轮单元并取得足够内容依据 → `teaching` |
| `teaching` | 有目标单元、足够来源依据，且该单元的必要前置基础已有理解证据；缺基础时先进入基础单元 | 讲解与示例；记录讲解要点和实际来源 | 讲解完成 → `understanding`，请用户说理解并等待 |
| `understanding` | 已完成讲解 | 用户用自己的话表达；只追问影响判断的缺口 | 正确 → `practice`；局部／核心错误 → `feedback` |
| `practice` | 已取得正确理解表达 | 情境判断／选择，按支架级别提供帮助 | 通过 → `recall`；错误 → `feedback` |
| `recall` | 应用练习通过 | 按预先确定的本轮题组逐题作答，作答前不展示答案 | 全部通过 → `consolidation`；部分或全错 → `feedback` |
| `feedback` | 实际回答出现错误或缺口 | 正确答案、具体原因、内容依据；必要时升支架或补基础 | 新情境检验对应原节点；反复卡住转 `teaching`；本轮结束可保留待巩固后整理 |
| `consolidation` | 本轮有可沉淀结果，或暂停前需整理部分成果 | 核对证据，保存状态，原位修订手册和更新说明 | 保存成功 → `recommendation`；保存失败 → 保留当前节点并说明 |
| `recommendation` | 当前环节已整理完成 | 依据最新状态推荐下一步和理由 | 继续 → 目标单元 `teaching` 或原待完成节点；无时间 → `paused`；全掌握 → `finished` |

正常续学时，`pending_question` 非空不跳到下一节点。用户的选项、解释、补充、询问、跳过和暂停是不同事件；问“为什么 B 不对”不算提交答案。明确跳过可清空该问题并记原因，不能生成虚构回答。用户明确修订目标或教学路线时可以先转 planning；旧待答项需作为未答历史保留在手册／修订记录中，记录不再立即恢复的原因，不伪造作答。只改问题措辞不能丢掉已有回答。

## 四、帮助级别 `support_level`

| 值 | 当前表现 | 方法与调整 |
|---|---|---|
| `full` | 不理解／补讲后仍卡住 | 完整例子与可核对的解题步骤，再让用户表达理解 |
| `guided` | 有概念但易混淆 | 部分示例、选项对比或填补一个关键步骤 |
| `coached` | 基本理解 | 用户先选或解释，必要时给一个提示 |
| `independent` | 已能正确解释并应用 | 独立判断新情境，答后反馈 |

有成功证据再逐步减少帮助；反复卡住增加帮助。它表示本单元当前所需支持，不是对用户的永久能力评级。答错后直接讲解正确关系和具体错误，不以反复提示代替反馈。

## 五、字段与持久化契约

schema_version=2 的顶层包含 revision、domain_slug、topic_slug、topic、可空的 map_ref、source_notes、diagnosis、session、units、assessments、updated_at。初始结构见 [state.json](../assets/state.json)。

| 字段 | 用途与取值要求 |
|---|---|
| domain_slug／topic_slug | 稳定领域与专题标识，小写英文、数字、连字符；无领域分类可用 general |
| map_ref | 无 Map 为 null；有 Map 为 path 与真实 section，文件和标题必须实际存在 |
| source_notes | 用户粘贴的小段原文，以 ID 映射原文；长材料保存或引用原文件 |
| diagnosis | completed、summary、assessment_ids；完成诊断必须有真实回答和结论。summary 说明所覆盖的前置概念、理解证据、待补缺口和路线；旧 completed 不能证明新目标所需基础全部已验证 |
| session | status、phase、active_unit_id、available_minutes、pending_question、repair_node、reason |
| units | 单元列表，保存当前学习轮与薄弱点；单元 ID 在路线调整时保持稳定 |
| assessments | 按实际发生顺序追加的回答与评价；旧原答不可被覆盖或删除 |
| revision／updated_at | 保存版本及带时区的实际更新时间；脚本成功保存后生成 |

每个单元字段：

- id、name、source_refs、prerequisite_ids：定位知识、来源和前置关系。
- status、mastered、support_level：单元流程、掌握证据和当前帮助程度，三个概念分开。
- taught、teaching_note：本轮是否已实际讲解，以及可用于恢复的讲解要点。
- stuck_count：同一知识点连续有效失败尝试的计数；工具错误、用户追问或暂停不计入。
- recall_target、recall_note：最终题组默认数量为 2；调整数量应在新题组开始前说明原因。
- checks.understanding、checks.practice、checks.recall：当前轮证据 ID；重学时清空这些引用和掌握标志，重置连续卡住计数，历史回答与弱点保留。
- weak_spots：description、assessment_ids、certainty=confirmed|possible、status=open|resolved；必须有实际回答证据。

每条 assessment 保存：唯一 id、unit_id（摸底可空）、node、完整 question、内部 answer_key 或判断标准、实际 user_answer、result=pass|partial|fail、具体 feedback、source_refs。最终检验还需 round_id，同一轮题组不能漏掉失败项。原答可另有归纳，但归纳不能取代原文。

source_refs 支持本地文件、http／https URL、inline:编号及明确的 knowledge:主题标记。内联编号必须有 source_notes 原文；通用知识标记不能伪装成外部验证。旧 schema_version=1 的 wiki_refs 与 Map 形式仍可读取，既有回答不为升级而重写。

pending_question 示例（结构演示，不是用户已发生的学习记录）：

```json
{
  "id": "q-understanding-1",
  "unit_id": "concept-1",
  "node": "understanding",
  "question": "说说你对这个概念的理解。",
  "answer_key": "能准确说明核心关系，不把条件关系说成必然保证。",
  "source_refs": ["inline:material-1"]
}
```

出题前内部答案已确定，展示时只输出题面；不能把整份含答案的内部 JSON 当成测验正文发给用户。source_notes、题面和原答均按必要范围保存，不将整个外部知识库复制进学习档案。

### 有脚本执行能力时

脚本就在本 Skill 的 scripts/learning_state.py，使用 Python 3.10+ 标准库。定位到 Skill 的真实绝对目录和学习工作目录后调用；以下路径需替换为实际位置：

```bash
python3 /实际位置/wiki-learning/scripts/learning_state.py validate /tmp/learning-candidate.json --root /学习工作目录
python3 /实际位置/wiki-learning/scripts/learning_state.py save /tmp/learning-candidate.json --expected-revision 0 --root /学习工作目录
python3 /实际位置/wiki-learning/scripts/learning_state.py index --root /学习工作目录
```

首次候选 revision=0，以未学状态建档；可以包含第一道待答摸底题，但不能带虚构回答。之后读取真实 state.json，以其 revision 作为候选和 expected-revision；成功后版本加一。脚本原子保存并拒绝过期覆盖，检查旧回答不可被删除；它不判断答案的专业正确性。

state.json 是权威状态，index.md 是可重建导航，学习手册是可读成果。脚本只写状态和总览，手册仍由 Agent 按实际内容修订。状态保存成功但总览失败时，返回 index=failed，修复后重建导航，不重复覆盖已保存状态。

### 有文件系统但不能运行脚本时

1. 读取当前状态和 revision，核对待答项、原答历史及当前节点。
2. 在临时候选文件中整理新状态，只追加实际回答，检查证据引用和节点条件。
3. 提交前再读目标版本；有冲突就重新核对合并，不能强行覆盖。
4. 将完整有效候选写入目标文件，成功后版本加一并填写实际时间；回读验证没有截断、丢失旧回答或错误状态。
5. 更新总览与实际需要修改的手册；清理不用的临时候选。说明未执行自动校验。

手工模式不能声称具有脚本的文件锁保护。无法可靠确认无冲突时交付候选与原因，保留当前对话状态，等待有能力的环境恢复。

### 没有文件系统时

当前对话中仍可学习与评价。暂停或准备跨会话时，交付恢复包：

- 专题、资料入口、当前节点和下一步的一段简短说明。
- 真实状态 JSON，含原题、实际回答、评价和待答项。
- 手册实际内容或明确指出应替换／追加的位置及更新说明。
- 下次将恢复包提供给 Agent 的一句使用说明。

当前仍有未回答题且用户要自测时，交付不含该题内部答案的阅读恢复包，并注明“未作答题的 answer_key 需恢复时从原来源补齐”；它是恢复材料，不是可直接提交的内部候选。恢复时保持原题，先核对来源、补齐内部标准再校验，不能让用户因恢复而提前看到答案。来源无法恢复时暂停该题评分。已经完成的回答和评价可以完整保留。不能说“已自动保存到记忆”或保证新会话不带资料也能恢复。

## 六、中断恢复与变更事件

| 事件 | 处理顺序 |
|---|---|
| 出题等待 | 先保存原题与标准，再展示题面；结束本轮，等待回答 |
| 收到答案 | 复核是否针对待回答题，依据标准评价，追加实际回答，清除已处理待答项，保存下一节点 |
| 题目有歧义／用户指出材料错误 | 暂停判分，保存 `blocked` 原因；确认后撤销旧题的考核用途，另出新题；不删除原答 |
| 用户暂停／时间到 | 保留原节点和原题，标记 paused；未完成部分不标完成 |
| 用户暂停以修订路线 | 保持 paused，核对来源结构与覆盖；保留旧题的未答事实，记录恢复时应先重建导航，不能自动回到旧测验 |
| 用户续接 | 读当前状态，校验引用，恢复 active；已有待答题只做必要提醒，不重讲全课 |
| 切换专题 | 先保存原专题；加载目标专题自己的状态；不同专题的回答、错点不混写 |
| 复习已掌握单元 | 保留历史，新学习轮清空当前 checks，转 in_progress；由新证据重新确定掌握情况 |
| 来源文件变化／断链 | 重新核对依据；受影响题目不凭旧答案评分，其余已验证记录不批量推翻 |
| 写入失败／版本过期 | 不重试覆盖；读取新状态核对合并，或保留恢复材料并说明保存失败 |

## 七、节点转换中的检查与错误分类

| 出现的问题 | 不应采取的动作 | 正确处理 |
|---|---|---|
| 只讲解、未等用户表达 | 将 taught 当 mastered | 等待 understanding 的实际回答 |
| 用户问一个选项为什么错 | 把追问计作答案 | 先解释，保留原待答项或说明换题原因 |
| 改写了题面后沿用旧原答 | 让证据看似通过 | 新题用新 ID，保留旧问题和答案 |
| 评分标准有误 | 改掉旧原答或继续判错 | 追加修正记录，当前 checks 指向新依据 |
| 提示后同题答对 | 当作独立掌握 | 换情境再检查，记录提示程度 |
| 资料读取失败 | 增加 stuck_count | 标记 blocked，处理材料缺口 |
| 时间到了 | 把本轮标 completed | paused，保留原 phase 和待答项 |
| 换专题 | 将另一专题答案写入当前单元 | 先保存原专题，再加载目标状态 |
| 全部单元流程走完但有未掌握项 | 标 finished | 保留 completed/mastered=false 或 needs_review，推荐巩固 |

检查旧答、当前 checks 和节点，才能知道下一步是等答案、补讲、练习、测验还是整理。题目内容的正确性、用户是否真的提交回答和学习效果仍需 Agent 与真实反馈核对，结构校验不能替代这些判断。

指定材料的整体覆盖另按 material-learning.md 核对。脚本确认单元证据齐全，不表示原文标题、知识点或方法步骤已覆盖；声明整份材料完成前仍须核对覆盖导航和用户对作者主线的理解。旧手册或某单元的 mastered=true 只支持对应范围。
