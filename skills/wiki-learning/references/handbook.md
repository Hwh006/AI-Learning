# 专题学习手册的持续维护

## 1. 手册的职责

手册是用户可阅读、可复习的学习成果。state.json 负责精确续学和证据引用，index.md 负责跨专题导航；这三者用途不同，不互相代替。用户与 AI 的逐字讨论另存，按 [讨论原文与归档](discussion-archive.md) 与手册知识点、来源正文建立关联。

同一批相关知识围绕一个稳定专题维护一份手册。有 Map 时，一般一个 Map 专题一份；无 Map 时按用户明确主题或已确定的学习单元群组织。重复学习、纠错和复习仍修订原文件，不每次创建新手册。

默认位置为 learning/<领域或 general>/<专题>/学习手册.md。文件夹不随日期或会话变化而改名。Skill 安装目录不保存用户学习记录。

## 2. 人读结构

完整起始模板见 [学习手册模板](../assets/handbook.md)。根据实际需要使用栏目，不为凑模板编造内容。

- 学习路线与当前进度：材料驱动或知识地图驱动方向、主线与补充依据、专题范围、单元顺序、已掌握／待巩固、当前停点和下一步；方向按 [学习方向](learning-paths.md) 判断，不靠资料数量区分。
- 指定材料的结构与覆盖：真实标题及父级链、每节知识点与方法步骤、必要术语及学习位置；记录未讲与已讲未检验，不以局部成绩代替覆盖。
- 知识点正文：问题、通俗理解、准确含义、例子、条件与常见混淆。
- 我的理解：实际表达及必要归纳，明确是原话还是整理。
- 正文与讨论归档：来源 raw、逐字讨论与消息位置，以及归档／Wiki 入库的实际进度；正文和讨论不能只有摘要。
- 错误与纠正：具体错误、原因、正确理解、练习证据及是否解决。
- 术语与速查：只有真正出现和有复习价值的内容。
- 旧记录的使用边界：哪些实际作答支持简化哪些内容，哪些基础仍不确定；手册出现过术语不等于用户已掌握。
- 更新说明：放在全文最后，记录本次真实新增、修正或补充。

## 3. 什么时候修改

有新增知识内容、用户理解表达、真实纠错结果或复习发现时修改。只有状态刷新、普通聊天或重新打开文件时，不机械重写正文，也不追加“今日学习结束”一类空说明。

未完成的单元可以保存真实的部分理解，标注“尚未检验／待巩固”，不能写成已掌握。手册中是否掌握应与当前状态及证据一致。

## 4. 怎样原位修订

1. 读取现有手册与当前知识点，定位稳定章节。
2. 区分新增、补充、纠正、已解决、待确认；只改变受影响内容。
3. 新知识点增加一个对应小节；已存在知识点修订原小节，不另建“第二次学习某概念”。
4. 保留原来仍正确的解释、条件、例子和链接。错误内容不能继续以正确知识出现；可以写“曾误以为……，现已澄清……”。
5. 题目原答保留在 state.assessments；逐字讨论独立保存。手册只选有复习价值的理解与代表问题，链接对应讨论消息，不在手册中堆整个聊天逐字稿，也不把精选摘录当作完整讨论档案。
6. 更新路线概览与弱点状态，在末尾写简短更新说明。
7. 回读核对正文、来源链接和更新说明，避免整本覆盖或产生重复章节。

## 5. 修订示例

第一次形成一个知识点小节：

```markdown
### 检索与生成的职责
- 关键理解：检索取得相关材料，生成还需要正确使用材料。
- 我的理解（原话）：……实际收到的表达……
- 易错点：命中相关资料不保证回答保留适用条件。
- 对应材料：……实际可用链接……
```

之后复习发现“条件遗漏”仍有混淆时，补充同一节的例子与纠正内容，不新增“第二次检索与生成学习”。如果随后通过新题，在该节标明问题已澄清；旧失败回答继续留在状态中。

示例中的省略内容是结构说明，不能作为实际用户原话直接写入。

## 6. 更新说明

放在文件最末，按实际发生时间追加一两句话，说明哪些内容变了；不用完整过程日志。

示例格式：“日期：补充检索与生成的职责边界；修正‘命中就一定答对’的理解，新增条件遗漏的例子。”

同一天多次补充可以合并成一个简短条目，但不能因合并丢掉重要修正。不需要记录打开文件、重建索引等纯技术动作。没有内容变化就不写新的更新说明。

## 7. 我的理解与来源的关系

用户的表达与资料观点分开。引语只保存实际原话；经 Agent 归纳的内容注明“整理”。正确的改写不能回填成用户已经独立说出或掌握的证据。

来源结论给对应引用，类比注明对应关系及边界。只有通用知识时明确标注，不虚构作者观点。项目事实、个人经历和材料中的一般方法不能混为一谈。

## 8. 题目与答案

未作答的当前题，其内部答案不提前写入用户阅读的手册。已完成题目可以选择代表题和解释作为复习材料；不把完整未来题库公开后再以复认成绩判掌握。

练习与最终题组的详细记录由状态文件维护。手册只保留能帮助理解、区分和纠错的例子，不需要为每个题目新建页面。

## 9. 与其他产物同步

先保存真实回答和状态，再修订手册，最后检查导航。若状态已保存而手册修订失败，明确哪些成功、哪些待完成，下次先补整理；不能撤销用户已给出的回答或假报全部成功。

状态与手册不一致时依据实际回答及检查结果核对。旧手册只证明曾记录这些内容，不能单凭正文恢复全部 mastered=true。

用户反馈“整体仍没懂”或指出章节缺失时，复核材料覆盖与局部成绩之间的范围差异，记录待重建的路线。保留原答，不将旧单元通过扩成整篇文章通过；新准备的目录、术语说明或方法步骤标为待教学，不冒充用户已经学习完成。

正文学习完成时，先核对原文与逐字讨论，再按归档 reference 自动接续已授权的 raw 与 Wiki 流程。手册显示实际归档清单和页面链接；尚有记录缺口或入库待办时保留，不由学习题目通过推定 Wiki 已完成。

## 10. 无文件能力时

输出实际手册正文或有明确位置的修改片段，以及末尾更新说明。给出预期文件名和下次恢复方式，不声称已写入磁盘。内容多时可以按知识点分段交付，但不能把计划或模板冒充已完成手册。
