# synthesis 综合页（跨单元全局不变量）

## 一句话定位

synthesis 页 = **wiki 的跨单元全局不变量**，形态是一条**定理**。

多个来源各自提供的观察，合起来约束出一条**没有任何单篇说过的结论**。它**不写**：某份素材说了什么（→ `sources/`）、这件事怎么做（→ `concepts/`）、该用哪个做（→ `comparisons/`）、你自己的判断（→ `notes/`）。

写得好不好，只看一条（05 §0 的完备性标准）：

> **证伪测试**：遮住正文，只看「一句话结论」和「适用域」。问读者 —— **在什么条件下，这条结论会不成立？**
> 答不出、或答「任何情况都成立」→ 不合格。那是口号，不是定理。

**结构齐全不等于会被推翻。** 全库 synthesis 现在 **0 页**，而 **15/22 个 concept 页已经被 ≥3 个来源支撑** —— 条件早满足了，卡点从来不是「源不够」。

**职责分工**：`index.md` 统一定义页型职责、适用条件和边界；本 Skill 定义本页型的字段、章节、执行步骤与校验。分类冲突按 `index.md` 处理，写作结构以本 Skill 为准，并同步修正不一致内容。

**标签自检**：写入或修改 Wiki 页时，按项目 `AGENTS.md` 的标签规则，从本页主旨、反复讨论的对象与关键机制提取具体检索词；每个主题标签须能在正文找到依据。素材类型标签另保留，不能单独充当主题标签。

| 本 skill 自带 | 什么时候看 |
|---|---|
| `scripts/verify_synthesis_page.py` | 每写完一页必跑，见第 6 步 |

## 触发条件

用：

- **回扫发现某主题被 ≥3 个来源覆盖**（`--probe` 直接给清单）
- 素材里在不同场合**反复出现同一判断**，但没有任何单篇把它说全
- 用户问「这几份材料共同指向什么」「这些说法合起来说明什么」
- 排查综合页在复述单个来源、或只是把 concept 页并排抄
- 排查结论不可证伪、没有反面证据、没有适用域
- 排查「支撑来源」表在凑数（每条撤掉结论都还成立）

不用：

- 只是讨论、回答、总结 → 不写页
- **只是把一篇素材的要点重述** → `sources/`
- **只是把几个 concept 页的内容并排抄一遍** → 停，那不是综合（那几页的「来源与证据」表已经做了这件事）
- 你自己的判断、评价、选择 → `wiki/notes/`
- 把多条记录汇总成清单 → `wiki/map/`
- **面试资料里的「推荐答案」** → 不是真实观察，不能当前提（同 04 §1）
- 某个项目怎么设计 → `solutions/`

## 输入契约

必填：

- **工作目录**：项目根。脚本路径（`skills/wiki-synthesis-page/…`）、素材路径（`raw/…`）、页面路径（`wiki/synthesis/…`）都相对它，命令请在这个目录下执行。
- **主题**，或一条**候选结论**。

补齐项：

- **已有页面**：`wiki/synthesis/` 现在为空；`wiki/concepts/` 有 22 页，`wiki/sources/` 有 41 页。**第一步永远是回扫 concept 页**，不是读 raw。
- **取材约束**：前提**必须落在已建 source 页上**。回 `raw/` 只用 01 的 `--locate` 核准原话与段号，**不许从 raw 直接取材**（05 §1）。
- **素材范围**：使用者自行提供的 `raw/` 原文；口语转写中的数值与术语须结合上下文核对。

## 执行流程

### 第 1 步 · 回扫，找有料但未综合的主题

```bash
python3 skills/wiki-synthesis-page/scripts/verify_synthesis_page.py --probe
```

列出 **`sources ≥3` 且「来源与证据」表 ≥3 行**的 concept 页 —— 这些是**有料**的。逐页问一句话：

> **这几行的共同约束是什么？**

有答案 → 进第 2 步。没答案 → 跳过，别硬写。

**为什么从 concept 页回扫，不从 raw 找灵感？** ① `sources` 字段机检，「有没有料」能算出来；② concept 页的「来源与证据」已在 IR 层去过噪；③ 它强制「先 ingest 再归纳」。

### 第 2 步 · 先摆前提，再看约束

**顺序不能反。**

| 做法 | 结果 |
|---|---|
| ✅ 先把这个主题下所有 source 的观察摆出来，再看它们共同约束了什么 | 结论是**被约束出来的** |
| ❌ 先有结论，再去挑支持它的来源 | 结论是**自己观点的注脚**（确认偏误，也是这个页型长期 0 产出的原因之一） |

把候选前提写成两列表：**来源 | 观察到什么**。这一步不写结论。

### 第 3 步 · 跑三个测试（动笔前，全部通过才写）

| # | 测试 | 怎么跑 | 不通过 |
|---|---|---|---|
| 1 | **撤前提测试** | 逐条撤掉前提，看结论**还成立吗** | **每条撤掉都还成立** → 本页不需要这些源，降级为 concept 补写 |
| 2 | **不可回溯测试** | 结论里每个名词，去来源原文里找 | 找不到 → 自己造的概念，删掉或标 `INFERRED` 并写依据 |
| 3 | **反向构造测试** | 构造「前提都成立但结论不成立」的场景 | 构造得出 → 结论太宽，**加限定并写进「反面证据」** |

**测试 1 是核心**，一次解决三件事：治「稀有」（改问哪几条是真的）、治「凑数」（装饰性来源被自己撤掉）、**生产「适用域」**（撤掉就不成立的那条前提，其内容就是适用条件）。

**硬要求**：支撑来源表**至少 2 行答「否」**。全是「是」→ 本页不该存在。

### 第 4 步 · 按节骨架写页

固定顺序：**7 个 `##` 节 + 1 个引言块**（05 §3）：

```
# {结论主题}

> 一句话结论                    ← 引言块，一行，必须可证伪

## 论证链                        ← 前提怎么推出结论，逐步给出处
## 支撑来源                      ← 表：来源 | 贡献了哪一步 | 撤掉它结论还成立吗
## 反面证据                      ← 必写，不许省
## 适用域                        ← 什么条件下结论不成立
## 不确定性                      ← 哪些环节是 INFERRED
## 待验证
## 相关
```

四处最容易写错：

- **一句话结论必须可证伪。** 写成「在 X 条件下，Y 成立」。❌「知识库质量很重要」「要注意成本和效果的平衡」。❌ 也**别写成问句**。
- **论证链的价值在步骤间的箭头。** 把三条前提各写一段 = 那是「支撑来源」表的活儿。必须是推导：1→2→3，最后一步才是结论。
- **反面证据 ≠ 不确定性。** 反面证据指向**外部**（素材反驳我）；不确定性指向**内部**（我哪里推得虚）。两节都必写，别互相抄。
- **支撑来源表三列全必填**，尤其「撤掉它，结论还成立吗」这一列 —— 这一列就是本 skill 存在的理由。

字段与正文结构见本 Skill 的骨架和自检说明；可运行的虚构 source 示例见 `examples/wiki-demo-source.md`。

### 第 5 步 · 查重（必做）

```bash
python3 skills/wiki-synthesis-page/scripts/verify_synthesis_page.py --dup
```

| 查什么 | 处理 |
|---|---|
| `synthesis/` 里已有同主题页 | 合并（前提并入来源表；新前提若使结论变化，改结论） |
| **`concepts/` 里已经讲过这个结论** | **本页不该存在** —— concept 页管「怎么做」，本页管「共同约束出什么」。若结论能在某 concept 页里读到，那是复述 |
| 结论与某 concept 页 title 高度重合 | 高度警惕：说明写的是概念而不是结论 |

**判据一句话**：**这句话能不能在某个 source 或 concept 页里逐字找到？** 能 → 那是复述，不是综合。

### 第 6 步 · 硬自检（不可跳过）

```bash
python3 skills/wiki-synthesis-page/scripts/verify_synthesis_page.py --page "wiki/synthesis/知识问答系统的效果上限由上游非模型环节决定.md"
```

脚本机检：frontmatter 必填与废弃字段 / **8 节骨架与顺序** / **一句话结论是否可证伪**（禁用语、问句）/ **支撑来源表三列是否齐、「否」的行数是否 ≥2** / **反面证据与适用域是否被占位语糊过** / 论证链是否有推导步骤 / 来源标注 `〔〕` 是否存在 / **是否残留 HTML 注释来源** / 相关节链接数与自环 / `sources` 是否只含 source 页。

**有 FAIL 就必须修完再交付，不许带着 FAIL 收工。** 修好重跑，退出码 0 才算完。

脚本验不了 §0 那条 —— **证伪测试**，只能人工做（05 §0）。

### 第 7 步 · 回填出链（双向）

**向外出链**：

| 提到什么 | 出链到 |
|---|---|
| 被综合的概念 | `concepts/`，至少 2 个 |
| 涉及的案例 / 项目 | `solutions/` 或对应 source 页 |
| 相邻的结论 | 其他 `synthesis/` |

**向内被引用**：`concepts/` 讲原理时引用结论、`map/` 导航、`solution` 的决策依据。

❌ **不要用 `[待创建: [[X]]]` 凑「相关」** —— 那是给 concept 页用的挂载方式，synthesis 的前提必须**已经存在**。

❌ **不要链自己。**

## 硬规则速查

| 规则 | 判据 |
|---|---|
| 先摆前提，再看约束 | 顺序反了就是确认偏误 |
| 结论必须可证伪 | 能写成「在 X 条件下 Y 成立」；答不出失效条件 = 口号 |
| 支撑来源表 ≥2 行答「否」 | 全是「是」→ 没有真前提，本页不该存在 |
| 反面证据必写 | 这是定理与猜想的唯一区别 |
| 适用域必写 | 推得再硬，前提不成立时也不能用 |
| 论证链要显式推导 | 三条前提各写一段 ≠ 论证链 |
| 不复述单源 | 能在某个 source/concept 页逐字找到 → 那是复述 |
| 前提落在 source 页上 | 不放 concept、不放 raw |
| 一条定理一个结论 | 两个结论 → 两页 |
| 来源标注用 `〔〕` | 行内，可见；不用 HTML 注释 |
| 推导一律标 `INFERRED` | 别把推断伪装成事实 |
| `derived: true` | ingest 跳过本页，避免自证环 |

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 把「总结」当「综合」往外倒 | 页面注水 | 撤前提测试（脚本 FAIL） |
| 凑够 3 个来源就建页 | 来源成了装饰 | 至少 2 行须答「否」（脚本 FAIL） |
| 只在 concept 页之间抄并排 | 与 concept 重复 | 本页要多出「约束」，不是「并置」 |
| 结论不可证伪 | 变口号 | 写成「在 X 条件下 Y 成立」（脚本 FAIL） |
| 结论写成问句 | 无法判真假 | 改陈述句（脚本 FAIL） |
| 没有反面证据 | 是立场，不是综合 | 必写，至少一条（脚本 FAIL） |
| 把不确定性当反面证据 | 两节混乱 | 外部反证 vs 内部推断，分开写 |
| 没有适用域 | 被拿去套不适用的场景 | 单列一节（脚本 FAIL） |
| 全部标 `EXTRACTED` | 推断伪装成事实 | 推导环节标 `INFERRED` |
| `sources` 里放 concept 或 raw | 可回溯链断裂 | 只放 source 页（脚本 FAIL） |
| 用 HTML 注释标来源 | 阅读视图不可见 | 行内 `〔〕`（脚本 FAIL） |
| 填 `created` / `updated` | 字段口径分裂 | frontmatter 以 05 §2 为准（脚本 FAIL） |
| 从 raw 直接取材 | 「有没有料」不可机检 | 前提落到已建 source 页 |
| 从面试资料建页 | 推荐答案不是真实观察 | 归 source / `queries/` |
| 用 `[待创建:]` 凑「相关」 | 前提本就必须已存在 | 链真实页面 |

## 边界

| 你想写的 | 该去哪 |
|---|---|
| 多篇共同约束出的新结论 | **这里** |
| 一篇文档的要点 | `sources/` |
| 这件事怎么做 | `concepts/` |
| A 和 B 该用哪个 | `comparisons/` |
| 两篇观点一致但推不出新东西 | 各自 concept 页的「来源与证据」节 |
| 我自己的判断 | `wiki/notes/` |
| 这个领域包含哪些方面 | `wiki/map/` |
| 某个项目怎么设计 | `solutions/` |

## 检索策略

| 场景 | 行为 |
|---|---|
| 「这些材料共同说明什么」「合起来看呢」 | 命中 `synthesis/` |
| 「X 是什么」「X 怎么做」 | 命中 `concepts/` |
| 「原文说了什么」 | 命中 `sources/` |
| 关联计算 | synthesis 与被综合的每个 concept 页各计一条边 |
| 去重解析 | 同主题的 synthesis 与 concept 页**都要返回**（一个给跨源结论，一个给原理） |

## 已知限制（必须告诉使用者）

1. **脚本查不出「该不该建页」。** 撤前提测试的结果（撤掉它结论还成立吗）**只能人工判断**；脚本只能检查这一列填了没有、答「否」的行数够不够（≥2）。
2. **脚本查不出「证伪测试」。** §0 的完备性标准是语义判断 —— 遮住正文问「什么条件下失效」，只能人工做。
3. **「可证伪」是启发式。** 脚本按禁用语（很重要 / 需要注意 / 视情况而定 …）和问句结尾判断，**查不出「句子形态像陈述但实质还是口号」**。
4. **`--probe` 只算得出「有料」，算不出「有结论」。** 它给的是 `sources ≥3` 且证据表 ≥3 行的 concept 页清单，**共同约束是什么**要人来读。
5. **证据表行数按 `## 来源与证据` 节的行数统计。** 页里若把该节改名或拆成多节，统计会偏低 —— 先按 03 v2 收口节名。
6. **`--dup` 的 title 重合检测基于字面。** 结论换个说法就查不出与 concept 页重复，需要人工读一眼结论。
