# 材料分类与学习拆解

在开始学习新材料、材料范围扩大或学习目标改变时读取本文件。只续接原单元时不重新拆整份材料。

本文件用于材料驱动学习。若用户只提出主题或要求按 Map 学习，先按 [学习方向](learning-paths.md) 从现有 Map 与 Wiki 组织整体路线；在地图学习中引入参考材料时，本文件只帮助理解该材料，不取代原专题主线。

[资料处理](source-materials.md) 负责取得实际内容、来源定位及不确定性，本文件负责按材料类型组织内容，[诊断与路线规划](diagnosis-and-planning.md) 负责根据用户基础确定教学起点与顺序。学习单元不等于原文切片、固定字数段、章节标题或视频文件。

本文件定义原文结构与逐节知识提取的产物；[教学呈现](material-learning.md) 负责把这些产物交给用户及按基础调整讲解，不再另造一套通用目录。[完整示例](examples/material-walkthrough.md) 演示结构、知识清单、路线与讲解怎样衔接。

## 1. 共同处理顺序

原文结构 → 逐节知识清单与关系 → 候选路线及能力目标 → 按目标补缺 → 展示范围并确认基础 → 按理解程度教学和验证。

1. 确认材料类型、用户目标和实际取得范围。未指定局部范围时，默认梳理全貌并覆盖主要知识，允许分多次学习；已有明确目标时直接沿用，不重复询问。
2. 先还原作者要解决的问题、内容结构与知识关系，再选择下面对应流程。PDF 是载体，粘贴是提供方式，均不自动决定内容类型。
3. 区分“整体结构暂定”和“当前可教学范围”。目录、标题、摘要只能用于导航；只取得部分正文时，只将有实际依据的内容用于讲解和出题，其他部分标明待读取。允许先学习可靠部分，不要求等待整本书或整套课程取得完毕。
4. 根据问题、依赖和可验证目标形成候选单元。影响核心主张理解、方法应用或适用条件的内容应纳入主要知识；旁支和重复例子可以合并或列为选读，不能只因难讲、篇幅短或没有标题就遗漏关键内容。图表、公式和操作画面中的关键关系也需纳入。
5. 先向用户展示材料主线、主要候选单元及学完能做什么。路线应简明，短时学习也保留全貌，不一次展开全部细节，不逐单元索取批准。说明它会随基础验证调整，而不是已确定用户全部具备前置知识。

## 2. 文章：先按原文结构，再逐节提取知识

### 梳理与提取

1. 阅读正文，先还原标题及子标题的父子层级、顺序和各节论述作用，再分析知识关系。原文结构是第一层骨架，不能仅当检索定位词，也不能一开始按自己熟悉的几个主题改写目录。开篇无标题的段落按实际功能定位，注明“无标题段落／教学归纳”；排除网页导航、推荐文章和装饰标题。
2. 在每个结构节点内逐段识别知识点。技术名词不只出现在标题，也可能藏在实施条目、图示或代码里；应从正文确认它的含义与作用。保留原词／中文对应及来源位置。标题译名需注明，翻译或归纳不伪装成原有标题。
3. 将实际内容按下列类别提取，允许同一项有多种性质；原文没有的类别省略，不为填表编造方法论或步骤。正文内容和教学补充分别标记。

| 类别 | 提取判断 | 学习时要说明什么 |
|---|---|---|
| 痛点／问题 | 作者指出原做法在哪里失效、为何要改变 | 触发场景、原做法、具体缺口 |
| 概念／技术名词 | 不理解就无法读懂机制或适用条件 | 是什么、所属角色、核心作用、与相近名词的区别 |
| 方法论／策略 | 组织判断或解决问题的原则、选择框架 | 解决什么、前提、取舍；没有独立框架时不硬升格 |
| 做法／机制 | 作者具体增加或改变的处理 | 输入、处理、产物、发生位置及原因 |
| 执行步骤 | 具有先后依赖的动作链 | 每步输入与结果如何交给下一步；并行项不写成串行 |
| 证据／指标／条件 | 支持结论或限制适用范围的信息 | 评估对象、比较口径、条件与结论边界 |

4. 识别各项的前置、因果、步骤、并列、比较和条件关系。跨节重复出现的知识点可合并讲解，但原节仍链接到它；单节有多个独立知识点可下拆。任何改序都保留原文章节对应和理由。

### 必须能交付的拆解产物

先有结构，再有知识点，最后才生成路线。用自然语言、缩进树或表格表达，字段含义如下；表格是示例格式，不要求所有材料都排成同样列数。

产物一：原文结构及其作用。

| 原文章节编号／父级链 | 本节在全文中的作用 | 主要问题或结论 | 取得范围 |
|---|---|---|---|

产物二：在对应结构下列出实际知识清单，不能只有“本节讲索引”。

| 知识点 ID | 原文位置 | 类型与名称 | 核心含义／本节作用 | 前置及关系 |
|---|---|---|---|---|

产物三：必要技术名词清单，用来发现遗漏与安排解释；词表不等于每个词都单独开课。

| 原词与中文对应 | 所属章节与角色 | 学习者需要理解什么 | 已有理解依据／待确认 | 计划讲解位置 |
|---|---|---|---|---|

产物四：方法步骤表。方法文章在知识清单基础上补此项；观点文章保留论证链，不硬补工程流程。

| 所属原文位置／步骤 | 输入 | 处理动作与原因 | 输出及下一步 | 条件／来源边界 |
|---|---|---|---|---|

例如检索改进类材料中，“实施时的取舍”不仅是一个标题，还需下拆区块边界、区块大小、区块重叠、嵌入模型、定制语境提示词及候选数量；BM25 算法、BM25 索引、向量模型和重排也须区分角色。Recall@20 放回实验方法／结果位置解释；不能因为它是核心术语，就把指标变成整篇学习的独立主线。可见 [填好的示例](examples/material-walkthrough.md)。

### 形成单元

- 先在原文结构下组织候选单元，再为它设定可解释、可判断或可完成的目标。完整方法的原因、动作和验证保持关联；过长时可按依赖分组，但不能让“可出题”成为选取内容的依据，或把步骤与适用条件拆散。
- 观点或论证类文章围绕主张、依据与成立条件学习，不硬补工程任务。方法或技术文章若目标包含实现，需组织输入、步骤、产物与验证，缺失部分按第 7 节补充。
- 检查主要主张是否都有解释依据，方法是否仍保留关键步骤，案例是否帮助理解机制，限制与反例是否被遗漏。无法由文章支持的部分列为缺口，不凭经验归为作者原意。

## 3. 书籍：全书骨架加章内知识单元

### 梳理与提取

1. 结合目录、前言和实际已读章节，梳理全书主题、各篇章的作用及承接关系。未读章节只能按目录暂定其位置，不能写成已确认的作者论点。
2. 在当前可读章节内提取核心问题、定义、论点、机制或方法，以及关键案例、条件和与前后章的联系。论证细节、图表和例题与其解释的知识保持对应。
3. 识别跨章前置知识、重复解释和新增内容。同一概念再次出现时，关联既有单元；新增条件、应用或反例补入相应知识点，不因名称相同就全部跳过。

### 形成单元

- 保留“全书 → 篇章 → 章内知识单元”的整体骨架，章内按知识关系拆分，不严格一节一单元，也不默认把全书跨章重组。
- 依赖前章但用户尚不理解时，先补相关基础再回到原章；作者叙述顺序与教学顺序不一致时，说明调整原因并保留原文位置。
- 当前章节之外只登记必要依赖和待读位置，不以全书规划代替正文阅读。检查候选单元能否回到章内原文、是否遗漏本章结论的关键依据，以及是否重复教授已证实的基础。

## 4. 课程：以目标与模块为骨架

### 梳理与提取

1. 梳理课程目标、模块、各课作用及模块依赖，区分课程承诺的目标与实际取得内容。可读范围以已取得的讲义、转写、视频或操作画面为准。
2. 提取概念讲解、教师演示、操作步骤、练习、评价标准和反馈，并定位到课时、页码或视频时间段。课件、字幕与画面互相补充，不把文件数量当作知识数量。
3. 将同一目标分散在多个视频中的解释、演示和练习关联起来；一段视频承载多个独立目标时可拆分。保留影响理解的先后依赖，不机械按每课时长切段。

### 形成单元

- 按可学习、可验证的能力形成单元，保留所属模块；一个单元可跨多个视频，但需记录各来源位置。
- 对操作目标，将概念与相应演示、输入、步骤、产物和验证连起来。教师演示不是用户完成实践，操作完成证据也不能由一道选择题替代。
- 若关键步骤只在画面中出现，不能仅凭字幕补造点击路径、参数或输出；先取得画面或可靠配套资料。缺口影响当前操作时标明未解决，先学有依据的概念或步骤。
- 检查单元是否回应模块目标、依赖是否具备、练习是否对应目标，以及是否把课程目录或教师演示误作用户掌握证据。

## 5. 粘贴材料：识别内容类型后分派

1. 从实际内容判断它是文章、书籍章节、课程稿还是独立片段；能识别时沿用对应流程，不因为是粘贴就统一当短文章，也不每次必问出处。
2. 多来源混贴时先区分来源和片段位置，再判断能否围绕同一问题组织。没有证据的来源、顺序或作者关系保留未知，不自行归为同一篇材料。
3. 对零散片段，提取当前能成立的问题、概念、主张、步骤和条件；不恢复未经取得的全文结构。“上述”“该方法”等指代或缺失前提会改变含义时，先读取可定位上下文；无法取得再针对缺口询问。
4. 保留用户原文与 `inline:` 等定位。短段可只形成一个单元，不为凑数量拆解；多个独立问题可分别成单元。检查结论是否超出片段范围，是否把改写、补充或猜测当成原文。

## 6. 候选单元与记录方式

每个候选单元明确以下内容，按实际存在的信息填写，不强行凑齐原文没有的类别：

| 内容 | 应说明什么 |
|---|---|
| 问题与能力目标 | 本单元解决什么，学完能解释、判断或完成什么 |
| 前置与依赖 | 需要哪些专业概念，与其他候选单元有什么关系；是否已具备留待基础验证 |
| 原文定位 | 实际取得的来源，以及章节、页码、时间段或粘贴片段位置 |
| 主要内容 | 必要的定义、机制、步骤、案例、证据、条件及其关系 |
| 缺口与补充方向 | 缺少什么、是否影响目标、应检索哪些知识库主题、还有什么待确认 |
| 验证方式 | 怎样检查理解和应用；目标包含操作时，需要什么用户产物或实际结果 |

从拆解到用户路线时，分别定义：

- 学什么：当前章节中必须理解的概念、技术名词、痛点、机制、方法与步骤，不只是章节名或“建索引”等动作标签。
- 什么顺序：以原文骨架为默认，给当前章节插入必需前置；注明调整理由及回到原文的位置。先自评基础不等于先把整套基础课程教完。
- 学完能做什么：用观察得到的行为说明范围，例如“能说明 BM25 与语义向量检索的区别”“能展示补语境步骤的输入与输出”“能指出区块边界影响哪些信息一起保留”。不能把“了解检索优化”当作可检查目标。

路线输出示例格式：

| 顺序／对应原文 | 必学知识点与关键术语 | 前置或改序理由 | 完成后可表现出的能力 | 本次详略依据 |
|---|---|---|---|---|

候选路线、覆盖范围、单元目标和未解决缺口写入学习手册的路线区；已有单元保持稳定 ID，正式纳入 `units` 后用现有 `source_refs` 和 `prerequisite_ids` 表示来源与依赖。具体位置与补充归属写在手册对应单元；`teaching_note` 只记录实际发生的讲解，不把规划写成已教内容。

不增加必填状态字段、不迁移历史 JSON、不改写旧回答，也不因新规则生效就重新开启已有课程。候选单元不是完成记录；检查教学完成和掌握证据继续遵守 [状态与节点](state-machine.md)。

## 7. 按目标和知识库补缺，再确定正式路线

1. 对照目标区分“材料已有依据”“必要基础”“实现或论证缺口”。原文没有说明的内容先登记，不静默补成作者观点。
2. 优先检索当前知识库与缺口相关的实际正文，核对适用条件；使用当前宿主已有检索能力，不依赖特定项目路径。项目接入按 [项目约定](project-integration.md)，无知识库时按 [资料处理](source-materials.md) 使用已有可靠资料或明确标注的通用知识。
3. 标明各项来自指定材料、知识库补充或教学推导，保留实际引用。只补支持本次目标的内容，不因找到相关页面就扩大课程；补充资料阶段不独立触发 Wiki。正文学习完成后按 [讨论原文与归档](discussion-archive.md) 接续已授权的归档和入库。
4. 只求读懂观点时，补足理解论证所必需的背景，不默认扩展为工程课程；目标包含实现时，补齐输入、执行步骤、产物和验证方式。知识库不足以覆盖的部分保持待解决，必要时按资料处理规则取得其他可靠依据；环境不足时区分可讲、可演示与尚未实际验证的范围。
5. 将候选单元交给 [诊断与路线规划](diagnosis-and-planning.md)，检查前置概念，先补缺口并验证，再调整顺序和当次学习量。新证据只调整受影响部分，保留作者结构、来源定位及用户已有作答。

结束材料拆解表示已有可解释的候选路线和覆盖边界，不表示用户已理解或会实现。不能用概念题通过推定实现能力已验证。
