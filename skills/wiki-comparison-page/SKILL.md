# comparison 对比页（选型解析）

## 一句话定位

comparison 页 = **wiki 的选型解析表**。把两个都能用的候选，按条件解析成「这个场景用哪个」。

它**不写**：A 或 B 本身是什么（→ `concepts/` 或 `entities/`）、选完之后的落地方案（→ `solutions/`）、多份素材合起来的新结论（→ `synthesis/`）。

写得好不好，只看一条（04 §0 的完备性标准）：

> **擦表测试**：把正文全部遮住，只留「一句话结论」和决策节。拿三个真实场景条件去套——**能不能唯一选出一个？** 三个条件答案全相同 → 该维度不构成判据；出现「视情况而定」→ 不合格。

**结构齐全不等于能决策。** 现有 2 页的判据列合规率 100%，但来源标注 **0 条**、决策节两页都在推诿、其中一页与 concept 页**标题一字不差**。

**职责分工**：`index.md` 统一定义页型职责、适用条件和边界；本 Skill 定义本页型的字段、章节、执行步骤与校验。分类冲突按 `index.md` 处理，写作结构以本 Skill 为准，并同步修正不一致内容。

**标签自检**：写入或修改 Wiki 页时，按项目 `AGENTS.md` 的标签规则，从本页主旨、反复讨论的对象与关键机制提取具体检索词；每个主题标签须能在正文找到依据。素材类型标签另保留，不能单独充当主题标签。

| 本 skill 自带 | 什么时候看 |
|---|---|
| `scripts/verify_comparison_page.py` | 每写完一页必跑，见第 5 步 |

## 触发条件

用：

- ingest 某份素材时，它**明确在做对比论证**（出现 vs / 相比 / 「X 与 Y 的区别」并展开）
- 素材给出**二选一的取舍结论**（「什么时候用 X，什么时候用 Y」）
- 素材给出**同一目标的两条路径**并各有优劣
- 用户问「A 和 B 怎么选」「该用哪个」「这两个有什么区别」
- 排查对比页在复述 concept 页、与 concept 页同名、或「怎么选」写成推诿

不用：

- 只是讨论、回答选择问题 → 不写页
- **只是两个页面有关联** → 只加 `[[链接]]`，不建页
- 用户自己想比较、素材没比 → 那是 `queries/` 的回答
- 要写 A 或 B 本身是什么 → `concepts/` / `entities/`
- **要写「向量 + 关键词怎么合成混合检索」** → `concepts/`（**选完还要把两者合成一个东西，那个合成物是 concept**）
- 只是某工具两个版本的参数差异 → `entities/` 里的版本对比
- **面试资料里的选型对比** → 对应 source 页 / `queries/`（04 §1 已定，不据此建页）

## 输入契约

必填：

- **工作目录**：项目根。脚本路径（`skills/wiki-comparison-page/…`）、素材路径（`raw/…`）、页面路径（`wiki/comparisons/…`）都相对它，命令请在这个目录下执行。
- **两个候选**，或指向对比论证的素材段落。用户只说主题时先用 `tools/wiki_lookup.py search` 按元数据查候选，再读已有页面，**不要凭主题猜候选名**。

补齐项：

- **已有页面**：`wiki/comparisons/` 现有 2 页。**建页前必查**，且要连带查 `concepts/` / `entities/` 里是否有**同名或近名**页（`--dup` 专查这个）。
- **素材范围**：使用者自行提供的 `raw/` 原文；口语转写中的数值与术语须结合上下文核对。

## 执行流程

### 第 1 步 · 反扫素材，找真的对比论证

```bash
# 从 raw 里扫对比线索，列出尚未建页的候选
python3 skills/wiki-comparison-page/scripts/verify_comparison_page.py --scan
```

输出分两组：**① 表格里的对比组**（`| 对比维度 | A | B |` 这类成组表头，结构化课程材料里最可靠）与**② 内联对比句式**（`A vs B`、`A 与 B 的区别`）。默认**跳过 `raw/interview_question/`**（04 §1 已定不作为生成依据）；要一起扫加 `--include-interview`。

**不要从「这个素材讲了什么」往下切**，那是产出无法决策的页面的原因。

按顺序问，**答案要具体**：

1. **素材里有没有两个候选被放在同一个决策点上？**
2. **它们是择一还是划界？**
3. **素材给出的差异维度有哪些？每个维度用什么可观察事实来分辨？**
4. **素材有没有给选择条件？没给就写明缺口，不许编。**
5. **这两个候选各自的 concept 页存在吗？本页与它们重复吗？**

### 第 2 步 · 判「该不该建页」

**三条信号，任一成立即建页**（04 §1）：

| # | 信号 | 长什么样 |
|---|---|---|
| 1 | 素材明确出现对比论证 | 「X vs Y」「X 与 Y 的区别」并展开说明 |
| 2 | 素材给出二选一的取舍结论 | 「能用 Workflow 解决的，优先用 Workflow」 |
| 3 | 素材给出同一目标的两条路径并各有优劣 | 人工质检 vs AI 质检 |

**三条都不满足 → 不建页。** 判别方法一句话：

> **这两个候选会在同一个决策点上被挑吗？**

「RAG」和「文本分块」不会——分块是 RAG 的一个环节，不是它的替代品。所以不建「RAG vs 分块」，只出链。

> ⚠️ **最常见的错误**：把「有关联」当成生成条件。**关联只生成链接，不生成页面。**

### 第 3 步 · 判类型：择一 还是 划界

**这一步决定第五节写什么，判错整页作废。**

| | 择一 `select` | 划界 `partition` |
|---|---|---|
| 问自己 | 这两条路**只能走一条**吗？ | 这两个概念**可以同时存在**吗？ |
| 第五节 | 「怎么选」 | 「边界规则」 |
| 输出 | 若 X 则 A，若 Y 则 B | 什么归 A，什么归 B + 共存接口 |
| 例 | Workflow 与 Agent、经销 与 代销 | 会员 与 CRM |

⚠️ **把划界型硬套进择一型，只能写出废话。** 实测：`membership-vs-crm` 页被塞进「怎么选」，最后写成「两类工作流同时存在时可并存」——**不是写作者的错，是节型不对**。识别信号：**如果你发现自己在写「两者可以并存」「不冲突」，那它就是划界型。**

**演进类**（Agent 1.0 与 Agent 2.0、人工质检与 AI 质检）按 `select` 处理，把旧方案当作候选之一。不单独立类型。

### 第 4 步 · 按节骨架写页

固定顺序 **7 节**，两类的差别**只在第 5 节**（04 §3）：

```
# {A} 与 {B}
> 一句话结论              ← 谁在什么条件下赢 / 边界在哪，一行
## 对比表                  ← 维度 | A | B | 判据              ★本页核心
## {A} 的适用边界          ← 什么时候该选 A
## {B} 的适用边界          ← 什么时候该选 B
## 怎么选 / 边界规则        ← select 用前者，partition 用后者      ★必写
## 判据来源                ← 表：对比维度 | 出处 | 置信度         ★必写
## 相关                    ← 3–6 个 wikilink，含 A、B 的 concept 页
```

四处最容易写错：

- **判据列是本页的签名。** 写成**可观察事实**，不是「要评估的东西」：✅「改动流程需要重新开发，还是改 Prompt 即可」；❌「视具体情况」「—」「仅作该课程说明，不能作为行业分类标准」（那是元注释，不是判据）。
- **不介绍 A 和 B 是什么。** 出现「XX 是一种……」「XX 的组成包括……」的完整段落，就是在复述 concept 页。**改写成一句话 + 出链。**
- **决策节必须给条件规则。** ❌「需要根据实际业务情况综合判断，建议结合团队能力决定」——读完还是不知道选什么。✅「分支能在开发前列全 → Workflow；列不全 → Agent；两者都有 → 外层 Workflow 包一个 Agent 节点」。
- **判据来源要逐维度对齐。** 对比表第一列有几个维度，这里就要有几行，一一对应。判据不是素材原话时标 `INFERRED`。

**位置标注形状**（沿用 01 分档，对比页**几乎都是多源**，**必须带来源短名**）：

```markdown
〔第三天 §一.1〕                                            ← 结构化材料
〔AI办公助手相关讨论 第 63 段「你看这1234567…」〕             ← 口语转写
```

段号与段首**不要手工数**：

```bash
python3 skills/wiki-source-page/scripts/verify_source_page.py \
  --raw "raw/record_cleaned_markdown/AI办公助手相关讨论.md" --locate "workflow 就是高级版本的RPA"
```

❌ **不要用 HTML 注释标来源**（`<!-- confidence: EXTRACTED | ... -->`）：阅读视图里不可见，等于没标。

字段与正文结构见本 Skill 的骨架和自检说明；可运行的虚构 source 示例见 `wiki/sources/示例素材.md`。

### 第 5 步 · 硬自检（不可跳过）

```bash
python3 skills/wiki-comparison-page/scripts/verify_comparison_page.py --page "wiki/comparisons/Workflow与AI Agent.md"
```

脚本机检：frontmatter 必填与废弃字段 / `comparison_type` 枚举 / **节骨架与类型是否匹配** / **第五节是否用错节名** / 一句话结论的禁用语 / 对比表是否有判据列、判据是否为空或占位 / **决策节有没有条件规则、有没有推诿句式** / **判据来源的维度是否与对比表逐行对齐** / 来源标注 `〔〕` 是否存在 / **是否残留 HTML 注释来源** / 相关节链接数与自环 / `[待创建:]` 格式。

**有 FAIL 就必须修完再交付，不许带着 FAIL 收工。** 修好重跑，退出码 0 才算完。

脚本验不了 §0 那条——**擦表测试**，只能人工做（04 §4.12）。

### 第 6 步 · 查重（必做，这是本页型最容易翻车的地方）

```bash
python3 skills/wiki-comparison-page/scripts/verify_comparison_page.py --dup
```

查三处：

| 查什么 | 处理 |
|---|---|
| `comparisons/` 里已有同主题页 | 合并（补足新来源的维度与判据，来源并入来源表） |
| **`concepts/` 里已有同主题页** | **不是"合并"，是分工**：concept 页留「是什么、怎么运作」，对比页只留「差异与选择」。**两页 title 不能相同** |
| 两个候选已在某 concept 页的「容易混的点」里 | 只是辨析 → **留在 concept 页，不建对比页** |

**❌ 现有反例**：`membership-vs-crm.md` 的 title 与 `concepts/会员管理与客户关系管理（CRM）.md` **一字不差**，sources 一个 2 条一个 3 条，且对比页在整段复述「会员管理是什么」。

**文件名**：新建页用 `wiki/comparisons/{A}与{B}.md`（中文，与全库一致）；已有页保持不变。

### 第 7 步 · 回填出链（双向）

**向外出链**：

| 提到什么 | 出链到 |
|---|---|
| A、B 本身是什么 | `concepts/` 或 `entities/`，**各出一次链，不展开** |
| 选完之后的实施方案 | `solutions/` |
| 判据涉及的指标口径 | `concepts/`（指标类） |

**向内被引用**：`concepts/` 讲原理时提到选型、`entities/` 的对象对照、`solutions/` 的技术选型、`map/` 导航。

❌ **不要把 A 或 B 的 concept 页名当成对比页自己的名字。** 现有 `membership-vs-crm` 页的「相关」首条写 `[[会员管理与客户关系管理（CRM）]]`——**那是它自己**，不是「相关」。

## 硬规则速查

| 规则 | 判据 |
|---|---|
| 候选必须真能互换 | 两者得在**同一个决策点**上被挑；只是有关联 → 只出链 |
| 必须解析出唯一结果 | 选不出就是 ambiguous；「各有优劣」是语法错误，不是风格问题 |
| 先判类型再写节 | 择一 → 「怎么选」；划界 → 「边界规则」。判错整页作废 |
| 判据列必须齐 | 每维度写**可观察事实**；空着、写「视情况」、写元注释都不行 |
| 决策节必须有条件规则 | 「若 X 则 A」；退化成「由业务确认」= 页面产出为零 |
| 不介绍 A、B 是什么 | 复述 concept 页 → 同主题双页无权威 |
| 对比页 name ≠ 任一方的页名 | 必须是「A 与 B」 |
| 判据来源逐维度对齐 | 对比表第一列 N 个维度 → 来源表 N 行 |
| 判据不是原话就标 INFERRED | 素材给差异、没给判据表述，是常态 |
| 来源必须可见 | 行内 `〔〕`，多源页带来源短名；不用 HTML 注释 |
| 素材的判断要保留 | 讲师说「能用 Workflow 就优先 Workflow」是素材内容，要写；「Agent 更好」是你的评价，不写 |

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 把「两页有关联」当生成条件 | 页面爆炸，且页面没内容 | 关联只加链接 |
| 对比表没有判据列 | 变成参数罗列，无法决策 | 每维度必写判据（脚本 FAIL） |
| 结论写「各有优劣」 | 等于没结论 | 落到「什么条件下选谁」（脚本 FAIL） |
| **决策节写「由业务确认」** | 页面产出为零 | 给条件规则，或写明素材缺口（脚本 FAIL） |
| **用「怎么选」写划界型** | 只能憋出「可并存」 | `comparison_type: partition` + 「边界规则」（脚本 FAIL） |
| **对比页里介绍 A、B 是什么** | 复述 concept 页 | 一句话 + 出链 |
| **对比页 title 与 concept 页同名** | 读者分不清权威，sources 还会不一致 | 对比页名为「A 与 B」（`--dup` 会报） |
| 对比页「相关」链自己 | 自环，暴露没分清页面身份 | 链 A / B 的 concept 页 |
| 判据来源与对比表维度对不上 | 有维度的判据无出处 | 逐维度一一对应（脚本 FAIL） |
| 判据其实是自己推的却标 `EXTRACTED` | 伪造可回溯性 | 标 `INFERRED` + 写推理依据 |
| 用 HTML 注释标来源 | 阅读视图不可见，等于没标 | 行内 `〔〕`（脚本 FAIL） |
| 为凑维度硬加行 | 表格变长，分辨力没提高 | 只列有实质差异的维度 |
| 划界型不写共存接口 | 「什么归谁」写了，落地时两边接不上 | 必写接口 |
| 从面试资料建对比页 | 推荐答案不等于真实经历 | 归 source / `queries/` |
| 填 `author: llm` / `created` / `updated` | 字段口径分裂 | frontmatter 以 04 §2 为准（脚本 FAIL） |

## 边界

| 你想写的 | 该去哪 |
|---|---|
| A 和 B 差在哪、该用哪个 | **这里** |
| A 本身是什么、怎么运作 | `concepts/{A}` |
| A 是个具体工具、有版本与替代品 | `entities/{A}` |
| **向量 + 关键词怎么合成混合检索** | `concepts/混合检索`（**合成物是 concept**） |
| 某类项目如何设计端到端方案 | `solutions/` |
| 素材原文说了什么 | `sources/` |
| 我实测过 A 和 B 后的选择 | `wiki/notes/` |
| 几份素材合起来能看出什么 | `synthesis/` |

## 检索策略

| 场景 | 行为 |
|---|---|
| 「A 和 B 怎么选」「该用哪个」 | 命中 `comparisons/` |
| 「A 是什么」 | 命中 `concepts/` 或 `entities/` |
| 「怎么把 A 和 B 合起来用」 | 命中 `concepts/`（合成物是 concept） |
| 关联计算 | comparison 与 A、B 的 concept 页各计一条边 |
| 去重解析 | 同主题的 comparison 与 concept 页**都要返回**（一个给选择，一个给原理） |

## 已知限制（必须告诉使用者）

1. **脚本查不出「该不该建页」。** `--scan` 只给候选对，判据是「这两个候选会在同一个决策点上被挑吗」——语义判断，只能人工。
2. **脚本查不出「擦表测试」。** §0 的完备性标准是语义判断——拿三个场景条件遮住正文套一遍，只能人工做。
3. **判据质量是启发式。** 脚本能查判据单元格是否为空、是否含占位语或元注释，**查不出「这个判据是否真的能分辨两者」**。
4. **「决策节有条件规则」是正则判断。** 按 `若/如果/一旦/优先/≥/则选` 等标记词判断，**有标记不等于规则可用**。列为 FAIL 时请人看一眼再改措辞。
5. **`--dup` 的 title 重合检测基于字面。** 改名、加括号缩写会绕过检测；`comparisons/A与B.md` 与 `concepts/A.md` 内容重复但 title 不同时，脚本查不出。
6. **`--scan` 只认显式对比句式。** `A vs B`、`A 与 B 的区别`能扫到；**口语转写里「这个和那个有什么不一样」这类自然表述扫不到**，需要人工扫正文。
