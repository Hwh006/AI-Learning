# 可选的项目接入

只在当前工作目录确实是该类项目时使用对应约定。没有这些目录、工具或配置时，直接按 Skill 的通用流程工作，不要求创建它们。

## AI_Learning 项目

### 资料与工作入口

- 当前项目规则由项目根 AGENTS.md 承接；偏好检索、意图识别、个人长期记忆的写入遵守项目机制。
- wiki/map/知识总地图.md 是领域导航，各领域 Map 在 wiki/map/；专题以实际标题为准。
- 知识正文在 wiki/；Map、标题和标签不能替代知识正文。
- tools/wiki_lookup.py 与 tools/wiki_retrieval.md 是已有候选定位和检索能力。存在且适用时复用；不在其他环境假定有这些工具。
- 原文、转写和其他事实材料按当前项目的实际目录与权限取证，不用 Wiki 补造用户经历。

### 两种学习方向的接入

指定材料并希望学习其中知识时，以该材料为主线，当前 Wiki 与其他材料负责补充；用户仅提出主题时，先读知识总地图定位领域，再读取对应 Map 分支与关联 Wiki。例如“我想学习 AI”先从 AI 地图梳理维度；“带我学这本 AI 书”仍按书籍主线，不因范围广泛改为地图驱动。检索和正文回读使用项目现有 Workflow，地图只导航。

材料完成后沿下述归档、Wiki 与 Map 同步流程回流；地图学习读取维护后的实际页面以获得更完善的学习要点，不预设当前地图已完整覆盖外部领域。

### 学习资料组织

按“领域／Map 专题”维护 learning/<domain>/<topic>/。例如 AI Map 的 RAG 专题使用 learning/ai/rag/，同一专题重复学习仍是同一状态文件和手册。

Map 变更时核对旧专题与新标题的对应；不能因为标题改名而另建一份丢掉旧进度。实际使用的 Wiki 关联存入 source_refs；Map 的 path 和 section 存入 map_ref。

### 链接与产物

对话中的文件链接遵守当前客户端要求，使用实际绝对路径。库内 Markdown 按项目约定使用可解析的 wikilink，或者核对后的相对文件链接。手册是学习成果，Wiki 写入由正文完成后的 raw 归档与既有入库流程承接，不直接用手册摘要覆盖知识页。

学习状态服务于本次及后续续学，按学习流程保存；个人长期偏好、经历与项目事实仍使用项目已有确认与提交机制。

### 正文完成后的归档与自动入库

仅在使用者已授权该流程时：以一篇文章、一个书籍章节或一个课程模块为边界，学习完成后自动关联归档来源正文与逐字讨论，并生成或更新 Wiki。既有授权覆盖逐份交接，不每份重新询问；用户明确要求只学、暂不入库或改变范围时以当前要求为准。

知识地图驱动学习以明确的专题或阶段为讨论归档范围；当前 Wiki 与原始证据继续复用，只将实际新增讨论、纠正或新取得材料增量移交。没有新增知识则记录复用或跳过，不重复把已有 Wiki 复制为 raw 或反复编译。

按本 Skill 的讨论归档 reference 取得实际 raw，再调用项目 `skills/raw-wiki-ingest/SKILL.md`，先读 `index.md` 并查重，逐份完成适用页面及校验，最后接续 `skills/wiki-generation-map-sync/SKILL.md`。沿用已有领域，不把学习讨论的角色或 AI 解释当成新的事实等级。

归档文件与清单位于 `raw/learning/`，动态入库记录使用项目已有 `outputs/` 位置；正文 raw 已存在时复用。此约定不授权扫描回填全部旧课程，也不向外部服务发布。

### 工具与双目录

Skill 自带 scripts/learning_state.py 是状态工具的唯一实现；项目 tools/learning_state.py 只是兼容 CLI 入口。任一入口都应执行同样的校验。

项目若维护 skills/ 与 skills/ 两个副本，应同步整个 Skill 目录；本 Skill 内部资源全部自包含，不需要按项目相对深度改写链接。AGENTS.md 继续作为高维工作入口，意图分类留在 intents/。

## 其他知识库或无知识库环境

已有 Map 时使用它；没有 Map 时由资料目录或学习目标构建路线。工作目录由用户当前项目或明确输出位置决定，不写进 Skill 安装目录。只有一个专题时可以使用 general 作为领域分组。

没有项目检索脚本时，使用宿主文件检索和正文读取能力。没有文件系统时输出恢复包；任何接入缺失都不能被解释为“用户没有掌握知识”。
