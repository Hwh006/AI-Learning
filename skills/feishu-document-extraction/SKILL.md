# 飞书文档截图提取

## 适用范围与入口

用户指定的飞书文档或 Wiki 页面无法正常复制、下载或导出，且用户要求提取正文时使用。只查看、总结或讨论页面时不自动创建 raw 文件。Codex 使用 Codex 内置浏览器；其他 Agent 工具使用已登录的 Chrome。记录文档标题、来源链接、可见作者/更新时间、采集日期和实际覆盖范围。

## 结构与文件粒度

1. 提取前先读取飞书目录/标题树及页面实际标题样式，记录一级、二级、三级标题的编号、标题和缩进关系，作为覆盖清单；不能仅依据当前屏幕可见的标题推断整章结构。
2. 只按页面实际使用的一级、二级、三级标题拆分文件。正文中的数字编号、加粗句、步骤名或目录中可点击但并非正式标题层级的条目，不独立成篇，完整保留在最近的上级正式标题文件中。例如“2、对 PDF 文件解析逻辑”属于其上级标题正文，不因数字编号而另建文件。不得把正式标题层级的兄弟小节合并在同一篇。父标题若仅作容器且无独立正文，不另造内容文件；其子标题各自成篇。父标题本身有独立正文时，另存为一篇。
3. 每篇文件开头写明本节标题和完整父级链，例如 `4、RAG > 4.2 RAG流程 > 4.2.1 数据提取 > 2、对 PDF 文件解析逻辑`，并包含来源链接、采集日期及作者/更新时间（可见时）。正文 H1 只写当前小节标题，不能用父章标题代替。
4. 文件名保留章节编号和标题，使用安全、可读的 Markdown 文件名。另建目录索引列出父子关系、各文件链接和采集状态；索引不是小节正文。
5. 开始时标记目录中所有目标小节为待处理；只有正文、图片及清洗检查都完成后才标记完成。交付范围须与覆盖清单逐项对应；有任何遗漏就明确列出，不得称为整章完整。

6. OCR 后的章节 raw、来源/标题链元数据、图片归属和交接按 [长文档提取 Skill](../long-document-extraction/SKILL.md) 执行。机器全文、可选汇编和目录索引分别标记 `ocr_output` / `aggregate` / `index` 且 `ingest_allowed: false`；最小小节 raw 使用 `section`。用户要求 Wiki 时调用 [Raw 逐篇入库 Skill](../raw-wiki-ingest/SKILL.md)，当前 raw 的 source 与适用 Wiki 闭合后再进入下一份；下一份可以补充前面生成的主题 Wiki。

## 截图与正文转写

1. 先按最小正式小节确认起止标题，再沿页面顺序滚动截图至下一正式标题。截图之间保留约三分之一至近一半视口的重叠，记录首末屏和滚动顺序；检查相邻屏重叠区域，确保没有漏段、重复录入或跳过懒加载内容。目录、无障碍树和页面可访问文本可辅助定位，不替代截图证据或 OCR。
2. 将小节截图按顺序拼成连续长图，保留足够重叠以便 OCR 识别衔接处。长图只用于 OCR 和覆盖检查，不能代替逐屏回看，也不能代替原文配图。
3. 使用项目 PaddleOCR 工具 `python3 tools/paddleocr_parse.py <截图或长图路径> --output <临时输出目录>` 识别截图。先尝试对拼接长图 OCR，并检查 `document.md`、`pages/page-*/page.md`、版面 JSON 和 manifest 中的识别/图片结果；若整张长图被识别为一个表格或图片、正文缺失、长边缩放导致文字难辨，改为对每张有重叠的视口截图分别 OCR。必要时仅裁掉浏览器界面和目录栏，不能裁掉正文、标题、图注、列表或代码。复用项目已有运行环境和缓存；不另装 OCR 引擎。OCR 输出是校对草稿，不是定稿。
4. 将逐屏 OCR 文本按截图顺序对齐，利用重叠内容去重并核对覆盖边界。逐屏对照原截图校正错字、数字、英文术语、列表顺序、代码、表格和图片锚点。页面可访问文本只能辅助核对，不能用来补造截图未覆盖的内容。无法辨认的字词标为 `[无法辨认]`；原文在截图中止或含义不全时照录可见内容并注明边界，不能按上下文补写。
5. 原文中编号、项目符号和表格按语义保留。表格转为 Markdown 时维持行列及表头关系；合并单元格或版面关系不清时注明限制。若 OCR 将表格、图表或图片误当正文，应按截图还原可读的文本，并仍单独保留原图。

## 配图处理（不得用 OCR 替代图片）

1. 页面截图只用于转写证据，不等于原文配图。识别到每一张原文图片后，单独打开图片查看器或原图预览，截取完整图片内容并保存至 `raw/assets/<文档短名>/`。不得用 OCR、文字描述、占位符或整屏浏览器截图替代图片本身。
2. 截图须包含原图的全部边界、图题、图例、标注与内容；只可裁掉查看器和浏览器界面，不可裁掉图像边缘、文字或图表元素。若原图本身被裁切，忠实保留并说明“来源图片边界处已截断”。过长图片可按连续区域分片，分片需标明顺序且不能遗漏重叠衔接处。
3. 按图片在来源中的出现顺序编号，核对原图计数与已保存图片一一对应。将 Markdown 图片嵌入归属它的最小小节，在原文对应位置插入，而不是集中放在文末或放进全章文件。图片应紧邻其上下文，不得猜测归属；归属不清时回到页面位置确认。
4. 每张图下用一两句描述实际可见内容、结构/字段/流程和可辨认标签；这是辅助说明，不能代替图片。图中无法辨认的内容标注不确定，不根据上下文推断图中文字。使用相对路径并检查目标文件存在且可读。

## 小节完成后的正文清洗

在完成一个小节的逐屏转写和配图定位后，再清洗格式；不得边看边概括或删减正文。

1. 去除仅用于视觉装饰、检查或复制残留的符号，例如独立出现的 `✅`、`👍`、`😄`、`•`。若符号承担真实列表层级、数学/编程含义或原文明确语义，则保留其含义并用一致的 Markdown 格式呈现；不能按字符一概删除。
2. 将“代码块”标签及带行号的逐行内容还原成 fenced code block。去除仅为界面显示的行号，保留代码、空行、缩进、注释、标点和语言标记；原文没有语言信息时不猜语言。代码行无法确认时在代码附近标出不确定内容，不静默改写。
3. 将原文列表转为 Markdown 列表，合并 OCR 将同一句拆开的换行，修复明显的视觉换行/多余空格，但不得改写、删掉重复段落或把原文升级为摘要。发现来源本身重复时照录，并可在元数据注明重复位置。
4. OCR 转写后的格式清洗不得改变论点、数字、术语、代码行为或章节归属。对清洗前后逐屏回看截图，重点核对代码、公式、列表序号、表格和图片锚点。只运行 OCR 而未回看截图，不能标记小节完成。

## 交付前逐节验收

对每个最小小节逐项确认：

- 目录中的标题在覆盖清单中恰好对应一篇正文文件；父级链和编号准确，未混入兄弟小节。
- 首屏至末屏连续覆盖，正文对照截图；没有用摘要代替原文，没有未经证实的补写。
- PaddleOCR 对长图或逐屏截图的实际输出已检查；已处理截图重叠区重复，并对校对后的正文再次逐屏核对。若 OCR 未产出正文或版面误分类仍未解决，标记部分提取并说明原因。
- 原文图片均单独完整截取、数量对应、归属正确，并嵌在正文对应位置；无“截图待补”等占位内容。
- 代码块围栏成对，代码格式/缩进/行号处理正确；装饰符号已清理，语义列表仍完整。
- Markdown 图片链接均能解析，输出目录索引覆盖全部完成和未完成小节。

任一项未通过，该小节保持未完成，并在交付时标出具体缺口。只采集不自动写入 Wiki；用户另外明确要求入库时，再调用 Raw 逐篇入库 Skill。

## 浏览器截图与文件保存

- Codex：使用 Codex 内置浏览器中已打开的飞书页面截取屏幕和原图预览。
- 其他 Agent 工具：使用 Chrome 中的飞书页面，不切换到 Codex 内置浏览器代替 Chrome。
- 保存后查看截图，验证图像边界和可读性。若浏览器无法截图、原图预览打不开或页面不能完整加载，说明具体阻碍及已完成范围，不得声称已完成 OCR/图片采集。
- 项目 PaddleOCR 使用说明见 [`tools/paddleocr_parse.md`](../../tools/paddleocr_parse.md)。截图 OCR 的临时输入、长图、临时输出和中间 OCR 文本在校对完成后清理；只保留规定的 Markdown 小节、目录索引和 `raw/assets/<文档短名>/` 中的原图截图。
