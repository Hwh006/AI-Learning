# 意图体系与执行条件

## 意图体系表

关键词和相似问法用于定位候选；最终按当前请求、必要前文、适用记忆、预期结果和交付位置判断。“其他实际任务”开放承接未列出的请求；同一请求可以包含多个相互依赖的意图。

| 意图名称 | 意图关键词 | 意图描述 | 意图相似问法 | 意图边界 |
|---|---|---|---|---|
| 知识库问答 | 是什么、为什么、怎么构建、如何理解、区别、原理、面试官问 | 用户希望理解知识、方法或业务问题，主要交付是对问题的有依据回答。默认检索并阅读相关 Wiki，再结合用户问题组织解释 | “知识库怎么构建？”；“面试官问：Harness 怎么构建？”；“跨境库存架构怎么构建？”；“意图和执行规则有什么区别？” | 要求形成特定方案、表格、体系或文稿时转内容设计与生成；解释指定原文时转指定材料解读；明确写入 Wiki 或 memory 时进入对应沉淀意图。询问本人经历时另核对记忆、简历或项目记录，不能由 Wiki 补造 |
| 内容设计与生成 | 输出、设计、构建体系、制定方案、起草、写一份、按这些维度、做一张表 | 用户希望依据要求形成新的方案、体系、分析、表格或文稿。先参考相关知识库，再把用户提供的场景、字段、约束和反馈转成所需产物 | “按五个维度输出意图体系。”；“根据我的场景设计处理流程。”；“参考知识库写一份方案。”；“将这个方案整理成对比表。” | 通用解释归知识库问答；以指定原文含义为目标时归指定材料解读；明确要求持久化到 Wiki 或 memory 时进入对应沉淀意图。实现可运行代码、Workflow 或脚本由工程任务承接；输出 Markdown 或修改规则文档不自动成为工程任务 |
| 指定材料解读 | 这里面说什么、作者怎么讲、这本书讲什么、读这篇、解释这一章、提取原文内容 | 用户指定网站、文章、书籍或文件，希望知道材料实际表达了什么。取得并阅读原文后提取内容、条件和例子，以指定材料为主要依据 | “这个网站里面说了什么？”；“这本书主要讲什么？”；“作者在这一章怎么解释记忆？”；“从原文中提取这一段的观点并解释。” | 仅提供链接或书名不表示要写库；围绕材料明确要求“生成 Wiki”或按约定要求“总结一下”时，解读可作为 Wiki 任务的前置环节。知识库可补充解释框架，但必须区分材料原意与补充分析；未取得原文不能凭印象作答 |
| 学习引导与复习 | 带我学、学习知识库、今天学什么、继续学习、复习薄弱点、考考我 | 用户指定材料时以材料为主线学习；只提出主题或要求按地图学习时，从当前 Map 与 Wiki 组织维度与学习要点，由 Agent 结合学习状态推荐内容，讲解后请用户表达理解，以判断／选择题检验并针对性纠错 | “根据 Map 带我学知识库。”；“今天该学什么？”；“继续上次的 RAG 学习。”；“复习我之前容易混淆的概念。” | 需要明确学习／复习意图；普通“是什么、怎么做”仍归知识库问答，不能自动开启教学和考试。面试模拟不在本发行版范围内；学习记录进入 learning/；使用者已授权时，正文学习完成后归档原文与讨论并接续 Wiki，个人长期记忆仍走确认机制 |
| Wiki 生成与改写 | 生成 Wiki、更新 Wiki、改写 Wiki、写入知识库、入库、总结一下、沉淀为知识 | 用户希望将给定资料或已讨论内容沉淀为当前知识库中的页面。先查已有 Wiki 并回读，再决定新建、合并或改写，按页型要求完成实际产物 | “把这篇文章生成 Wiki。”；“把刚才讨论的内容总结一下。”；“把这部分补充到已有 Wiki。”；“根据这本书完善知识库。” | “总结一下”默认写库限于资料或知识讨论语境；“只在聊天里总结”“不要写库”“先给草稿”按明确交付限制执行。目标为 memory 时转记忆沉淀；只解读原文不自动写库；不能每次都新建重复页面 |
| 记忆沉淀 | 总结成记忆、保存为记忆、记住这条要求、更新这条记忆、把这段经历记下来 | 用户明确希望保存、合并或修正个人经历、偏好、原则、目标、项目、任务或决策方式。先读记忆目录说明，按内容分类查重，再按确认范围整理提交 | “把刚才的回复要求总结成记忆。”；“记住，以后介绍项目按这个顺序。”；“把这段项目经历保存到记忆里。”；“更新我之前的这个偏好。” | 可复用的主题知识归 Wiki，不能统一存为偏好；“以后可能……”等未来表达本身不自动授权保存。只有明确保留请求才进入此意图，其他任务中的记忆候选仍独立识别；具体写入范围未确认时按 [AGENTS.md 的写入前确认](../AGENTS.md#写入前确认)处理 |
| 其他实际任务 | 线索随任务变化，如编写代码、实现脚本、运行、调试、检查文件、修改配置 | 承接前五类之外的实际请求，由用户目标、目标对象和交付要求决定执行入口。构建代码、可运行 Workflow 或脚本属于工程执行任务，默认直接依据目标文件、接口和工具说明推进 | “写一个元数据查询脚本。”；“实现这个 Workflow 并运行验证。”；“修复这个报错。”；“检查当前配置。” | 此类别不表示一律免查知识库：仍包含分析或内容设计子任务时，该子任务按通用取证规则查库。不能仅因出现“构建”“Workflow”或输出 Markdown 就判为工程任务；例如“解释 Workflow 的设计方法”是知识库问答，“输出一份 Workflow 方案”是内容设计与生成 |

## 意图对应的后续执行条件

所有意图都须满足 [AGENTS.md](../AGENTS.md) 的每轮偏好检索与任务承接要求。知识问答、分析、方案设计、体系构建和内容撰写默认参考相关知识库；已读且仍适用的正文可复用。构建代码、可运行 Workflow 或脚本等工程执行默认免查 Wiki，知识性设计子问题按需查库。指定原文和个人事实保持各自的权威来源，不能用 Wiki 推导用户经历或冒充作者原意。

| 意图 | 后续执行条件 | 执行约束与交付 |
|---|---|---|
| 知识库问答 | 问题对象与必要上下文已明确；按 [Wiki 检索 Workflow](../tools/wiki_retrieval.md) 取得相关正文，或已有仍适用的正文 | 结合用户问题和适用记忆回答，引用实际采用的知识页。库内不足时说明缺口，补充推导与外部资料须区别来源；本人经历另查项目证据 |
| 内容设计与生成 | 目标产物、用途、字段或形式及当前约束可从请求和前文确定；已参考相关知识库；存在适用方法时从 [Skills 目录](../skills/) 选择入口 | 按本轮要求和已确认反馈生成或修订产物；指定文件写入指定目标，要求草稿则交付草稿。仅要求输出内容不自动授权写入 Wiki 或 memory；材料不足以支撑的部分保留为推导或待确认 |
| 指定材料解读 | 指定来源已确定，且取得了覆盖本次问题的实际正文；尚未取得时先选择来源对应的读取能力 | 以原文支持的内容回答并标明出处和实际范围；知识库只作补充且与作者观点区分。仅提供书名、链接或未读目录不能视为已读原文 |
| 学习引导与复习 | 用户明确希望逐步学习、续学、复习或检查知识掌握；先区分材料驱动与知识地图驱动：前者按指定材料组织并查库补充，后者先读当前 Map 分支和关联 Wiki，再形成学习要点；读取对应专题状态，无状态时建档并验证基础 | 按 [wiki-learning](../skills/wiki-learning/SKILL.md) 的状态与节点定义推进讲解、理解表达、练习、检验和纠错；在当前对话学习，按专题持续维护状态、手册与逐字讨论。材料驱动的一篇文章、一个书籍章节或一个课程模块完成后，将实际正文 raw 和讨论 raw 交给 Wiki 生成与 Map 同步；地图专题或阶段完成后只增量移交新讨论、纠正或新材料，复用已有 Wiki 和来源，分别核验学习、归档与入库进度。用户明确只学或暂不入库时遵其要求；个人长期偏好仍走记忆确认规则。普通知识提问不自动开始考试，学习中临时追问处理后恢复原节点 |
| Wiki 生成与改写 | 用户明确要求生成、更新 Wiki，或在资料/知识讨论语境要求“总结一下”；待处理材料或讨论范围可确定，已有相关 Wiki 已检索回读；按 [页型入口](../index.md) 和 [Skills 目录](../skills/) 核对写入与验收要求 | 决定新建、合并或改写并完成实际页面及必要校验；原文入库按对应方法逐份处理，讨论内容区分事实与推导。内容校验后自动接续 [Wiki生成后同步Map工作流](../skills/wiki-generation-map-sync/SKILL.md)，增量更新已有领域地图并通过覆盖校验后才报告任务完成；用户明确排除地图更新时遵其要求。“只在聊天总结”“不要写库”“先给草稿”等明确限制优先；交付全部实际新增或修改的页面路径 |
| 记忆沉淀 | 用户已明确要求保存或修正记忆；已按 [记忆目录说明](../memory/README.md) 分类、查重并读取相关正文，具体内容与范围符合 [写入前确认](../AGENTS.md#写入前确认) | 按 [整理规则](../memory/写入机制.md) 和 [提交 Workflow](../memory/写入Workflow.md) 新建、合并或修正对应记忆；已有具体确认不重复询问，缺少确认则先展示拟变更内容。交付实际文件，不将主题知识统一存为偏好 |
| 其他实际任务 | 用户实际目标、目标对象及操作范围可确定；目标文件、接口、状态或工具说明足以支持动作 | 按目标对象和适用方法执行并验证实际结果。工程执行直接依据项目规则、代码和接口；分析或内容设计子任务仍参考知识库。出现“构建”“Workflow”或输出 Markdown 本身不构成免查知识库的理由 |
